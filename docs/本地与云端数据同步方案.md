# 本地与云端数据同步方案

针对"本地存储与线上数据同步的稳定方案"，结合现有代码逻辑，梳理了一套**清晰、可靠、低成本**的同步机制。核心思想是**"本地优先、按需同步"**，既保证操作流畅（零数据库连接），又保证数据最终一致，同时**最大限度节省 Neon Postgres 免费额度**（每月100小时计算时间）。

---

## 一、整体架构设计

| 组件 | 作用 | 特点 |
|------|------|------|
| **本地存储 (localStorage)** | 日常读写的主要数据源 | 秒级响应，不消耗数据库时长 |
| **云端数据库 (Postgres)** | 权威持久化存储，跨设备共享 | 仅在"同步"操作时连接，按需唤醒 |
| **同步接口 `/api/admin/sync`** | 提供 `pull`、`push`、`merge` 三种模式 | 支持冲突解决与数据保护 |

**数据流向**：  
`本地(主) ←→ 一键同步(merge) ←→ 服务器(权威)`

---

## 二、同步模式详解（三种场景）

| 模式 | 触发时机 | 行为 | 适用场景 |
|------|----------|------|----------|
| **pull（拉取）** | 新设备首次使用、数据损坏、想丢弃本地改动 | **强制用服务器最新数据覆盖本地**（本地改动会丢失） | 换设备、数据回滚 |
| **push（推送）** | 离线批量操作完成后，集中上传 | **仅把本地新增/修改/删除推送到服务器**，不合并服务器上的新数据 | 离线工作后统一上传 |
| **merge（合并）** ✅ **推荐日常使用** | 完成一批操作后（如下班前） | **双向合并**：先拉取服务器数据，与本地合并（时间戳比较），再推送本地变更到服务器，最终再用服务器快照覆盖本地，保证三方一致 | 日常同步，兼顾安全与效率 |

**核心优势**：  
- `merge` 模式自动处理冲突，不会盲目覆盖。
- 每次同步只唤醒数据库一次（约5分钟计算时间），每天同步1-2次，每月消耗远低于100小时。

---

## 三、冲突解决规则（防丢数据）

| 数据类型 | 冲突处理原则 | 说明 |
|----------|--------------|------|
| **产品** | 比较 `updated_at`，新版本覆盖旧版本 | 本地编辑时间戳更新则推送，服务器新则拉取 |
| **兑换码** | <ul><li>**`used` 状态**以服务器为准（真实激活）</li><li>其他字段比较 `created_at` / `updated_at`，取新</li></ul> | 防止本地误改已使用状态 |
| **激活记录** | **服务器绝对权威**，本地只做缓存；已存在的记录不覆盖，只补充缺失字段（如 `device_id`） | 激活是线上行为，本地不可伪造 |
| **删除操作** | **删除保护**：推送前会查询服务器，若目标不存在则拒绝删除，防止孤立删除标记误删 | 避免本地删除标记误删线上数据 |
| **计数器** | 取服务器与本地的大值，避免回退 | 产品ID自增永不回退 |

## 四、推荐操作流程（日常使用）

1. **日常操作（99%时间）**  
   - 打开管理后台，所有增删改（添加产品、生成兑换码、删除过期码）**全部在本地进行**，界面秒级响应，**不连接数据库**。
   - 数据自动保存在浏览器 localStorage，即使断网也可继续操作。

2. **完成一批重要操作后（如下班前）**  
   - 点击顶部 **`⬆⬇ 一键同步（merge）`** 按钮。
   - 系统将自动执行：拉取服务器最新数据 → 合并本地变更 → 推送本地变更 → 再拉取一次确保一致。
   - 整个过程约1-3秒，仅消耗一次数据库激活（约5分钟计算时间）。

3. **换设备/恢复数据**  
   - 在新设备打开后台，点击 **`⬇ 仅拉取（pull）`**，即可从服务器恢复全部最新数据，本地旧数据被覆盖。

4. **定期备份**  
   - 在"设置"或"数据同步"页面点击 **`📥 导出本地数据为 JSON`**，保存备份文件，防止浏览器清理缓存。

---

## 五、为什么这样设计能节省数据库时长？

- **按需连接**：只有点击同步按钮时，才会唤醒数据库（Vercel Serverless + Neon 自动暂停）。  
- **默认无轮询**：界面不自动定时拉取数据，避免每5分钟唤醒一次。  
- **批量操作**：一次同步上传所有变更，而不是每条操作都触发写入。  
- **实测预估**：每天同步2次，每月约唤醒 2×30×5分钟 = 300分钟 = **5小时**，远低于100小时免费额度。

## 六、常见问题与预防

| 问题场景 | 原因 | 解决方式 |
|----------|------|----------|
| 同步后本地数据丢失 | 误用 `pull` 覆盖了本地未推送的改动 | 日常使用 **`merge`**，不要轻易用 `pull` |
| 删除操作报错"服务器不存在" | 删除保护生效，该ID在线上不存在 | 先在服务器同步一次，确保数据一致再删除 |
| 激活记录本地不更新 | 激活记录由服务器产生，本地只读 | 点击 `merge` 或 `pull` 刷新缓存 |
| 两台设备数据不一致 | 未同步导致分叉 | 在任意一台设备执行 `merge`，另一台执行 `pull` 即可统一 |
| 浏览器存储满 | 本地缓存过多 | 执行 `merge` 推送所有数据后，可在"设置"中清空本地数据，再 `pull` 恢复 |

---

## 七、额外加固建议

- **开启"删除保护"**（设置中默认开启）：防止误删线上数据。
- **开启"自动清理删除标记"**：同步成功后自动清空本地删除队列，避免堆积。
- **定期导出一份 JSON 全量备份**：放在云端或本地硬盘，作为最终物理备份。
