# 直接生成激活码功能设计

## 一、需求概述

在后台新增一个"直接生成激活码"页面，管理员可跳过兑换码激活流程，直接输入设备ID、选择产品、设置月数，一键生成激活码并记录。

### 与现有流程的区别

| 流程 | 现有方式 | 新方式 |
|------|---------|--------|
| 步骤 | ① 生成兑换码 → ② 用户输入兑换码+设备ID → ③ 系统生成18位激活码 | ① 管理员直接输入设备ID+产品+月数 → ② 系统生成18位激活码 |
| 兑换码 | 预先生成，发放给用户 | 自动生成，无需用户操作 |
| 适用场景 | 正常用户自助激活 | 测试、手动补发、客服处理 |

## 二、页面设计

### 2.1 表单字段

| 字段 | 类型 | 说明 |
|------|------|------|
| 设备ID | 文本输入 | 用户手环/手表的设备ID，任意字符，系统自动取后4位 |
| 产品 | 多选下拉 | 从已有产品列表中选择，支持多选（选多个产品则生成多个激活码） |
| 激活月数 | 数字输入 + 永久复选框 | 输入月数(1-98)，勾选"永久"则设为 99（2位数字上限） |
| 兑换码 | 自动生成 | 4位大写字母+数字混合，自动生成并显示 |

### 2.3 交互逻辑

1. 输入设备ID → 实时显示后4位预览
2. 选择产品 → 多选，显示已选标签
3. 输入月数或勾选永久 → 互斥，勾选永久后月数输入框禁用
4. 点击生成 → 每次生成新的兑换码（随机4位）
5. 结果区展示所有生成的激活码，含：产品名、激活码、兑换码、设备ID、月数、到期时间
6. 一键复制：复制全部激活码或全部兑换码

## 三、后端 API

### 3.1 新建 `POST /api/admin/direct-activate`

```javascript
// 请求
{
  "deviceId": "Aa09",
  "productIds": ["01", "02"],   // 产品ID数组
  "months": 12                    // 月数，1-98，99=永久
}

// 响应
{
  "success": true,
  "results": [
    {
      "productId": "01",
      "productName": "课程表",
      "activationCode": "012345678901234567",
      "redeemCode": "XK9M",
      "deviceId": "Aa09",
      "months": 12,
      "expiresAt": "2027-09-01T00:00:00.000Z"
    },
    {
      "productId": "02",
      "productName": "表盘",
      "activationCode": "987654321098765432",
      "redeemCode": "B7F2",
      "deviceId": "Aa09",
      "months": 12,
      "expiresAt": "2027-09-01T00:00:00.000Z"
    }
  ]
}
```

### 3.2 后端处理流程

```
for each productId:
  1. 生成唯一兑换码 generateRedeemCode() → 4位 A-Z,0-9
  2. 确保兑换码不重复（检查 auth:redeem:{code} 是否已存在）
  3. 生成激活码 generateActivationCode(productId, deviceId, months, redeemCode)
  4. 保存兑换码到 Redis: auth:redeem:{code} = { used: true, product_id, ... }
  5. 保存激活记录到 Redis: auth:activation:{actCode} = { ... }
  6. 更新集合: auth:redeem_codes, auth:activation_codes
  7. 返回结果
```

### 3.3 安全校验

- 需要 Vercel 管理员认证（复用 requireAuth）
- 设备ID 校验（非空，合法字符）
- 产品ID 校验（必须存在于产品列表）
- 月数校验（1-98 或 99）
- 兑换码唯一性（冲突时重试最多 3 次）

## 四、数据存储

### 4.1 兑换码记录

```
Key: auth:redeem:{code}
Value: {
  "code": "XK9M",
  "product_id": "01",
  "duration_months": 12,
  "used": true,
  "used_device_id": "{sha256(deviceId)}",
  "generated_activation_code": "012345678901234567",
  "created_at": 1693567890000,
  "used_at": 1693567890000,
  "source": "direct"           // 标记来源：直接生成
}
```

### 4.2 激活记录

```
Key: auth:activation:{activationCode}
Value: {
  "activation_code": "0123456789...",
  "device_id_hash": "{sha256}",
  "device_id": "Aa09",
  "product_id": "01",
  "duration_months": 12,
  "redeem_code": "XK9M",
  "generated_at": 1693567890000,
  "expires_at": 1725190290000,
  "source": "direct"            // 标记来源：直接生成
}
```

### 4.3 来源标记

新增 `source` 字段区分激活来源：

| source 值 | 含义 |
|-----------|------|
| `"user"` | 用户通过兑换码自助激活 |
| `"direct"` | 管理员直接生成 |

## 六、文件变更清单

| 文件 | 操作 | 说明 |
|------|------|------|
| `api/admin/direct-activate.js` | 新建 | 直接生成激活码 API |
| `api/messages.js` | 删除 | 消息中心已移除，释放 Vercel 函数名额 |
| `api/postgres-messages.js` | 删除 | 同上 |
| `admin_Dx23.html` | 修改 | 新增标签页、菜单项、表单、结果区 |
| `lib/crypto.js` | 无需修改 | 复用现有 generateActivationCode |
| `lib/validate.js` | 无需修改 | 复用现有校验函数 |

> **Vercel 免费版限制**：最多 12 个 Serverless Function。当前 12 个已满，需删除 2 个废弃的消息 API 腾出名额，新增 direct-activate 后共 11 个。

## 七、边界情况

| 场景 | 处理 |
|------|------|
| 设备ID 为空 | 前端校验，提示"请输入设备ID" |
| 未选择产品 | 前端校验，提示"请至少选择一个产品" |
| 月数输入 0 或负数 | 前端校验，min=1 |
| 兑换码冲突 | 后端重试最多 3 次，仍冲突则报错 |
| 产品已被删除 | 后端校验产品是否存在，404 提示 |
| 同一设备+产品重复生成 | 允许（每次生成新的兑换码和激活码） |
| 生成失败部分成功 | 事务性处理，全部成功或全部回滚 |

## 八、总结

| 要点 | 说明 |
|------|------|
| 新增页面 | 后台"直接生成"标签页 |
| 新增 API | `POST /api/admin/direct-activate` |
| 核心流程 | 输入设备ID → 选择产品 → 设置月数 → 自动生成兑换码 → 生成18位激活码 → 记录 |
| 多产品 | 支持一次选择多个产品，每个产品生成独立激活码 |
| 永久 | 勾选"永久"后 months=99，2位数字上限 |
| Vercel 限制 | 删除废弃的 messages.js + postgres-messages.js，腾出函数名额 |
| 来源标记 | 新增 `source: "direct"` 区分直接生成与用户激活 |
| 安全 | 需管理员认证，设备ID校验，产品存在性校验 |
