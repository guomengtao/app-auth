# 访客记录 / 统计写入问题：分析与核验

> 问题描述：**访客记录、日志写入没生效**；并需要核实访客记录是否真的写进了 Supabase、是否永久保存。
>
> 核验时间：2026-09-23 09:2x（CST）。所有结论都有 Supabase 实查数据或线上实测支撑。

---

## 一、结论摘要

| 判定 | 结论 |
|---|---|
| 是否写进 Supabase | ✅ **是**。访客记录走 `lib/redis.js`（Postgres 代理）落到 Supabase 的 `kv_lists` / `kv_strings` / `kv_sets` / `kv_zsets`，**不是 Upstash** |
| 写入是否生效 | ✅ **生效**。实测触发一次埋点后，`stats:recent` 立即新增一行、PV 1→2、页面排行出现新路径、UV 2 |
| 是否「永久保存」 | ❌ **不是**。只有 `ip_lookups`（35 行，地理信息）是永久表；PV/UV/页面统计 **7 天过期**，访客明细列表只保留 **约 100 条** |
| 「看起来没写入」的真正原因 | 🔴 **B1 时区错位**（最可能）：日期分桶用 **UTC**，而限流等其它模块用 **UTC+8**，导致**北京时间 00:00–08:00 的访问被统计到前一天**；🔴 **B2 地区为空**：Vercel 对国内 IP 常只给 country，`rg`/`ci` 全空，记录看起来"没内容" |

---

## 二、实测证据（Supabase 实查）

### 2.1 触发一次埋点，写入确实生效

```bash
curl -X POST -H "Content-Type: application/json" \
  -d '{"path":"/bugcheck-visitor-track.html"}' \
  "https://app-auth.gudq.com/api/activate?section=visitor-track"
# => {"success":true,"isNewVisitor":true}   HTTP 200  0.65s
```

随后查库：

```sql
-- 访客明细：新增了刚写入的这条
select idx, value from kv_lists where key='stats:recent' order by idx desc limit 1;
-- idx=744  {"h":"30968df7","p":"/bugcheck-visitor-track.html","u":"curl/8.7.1","t":1790126243092,
--           "ip":"36.113.30.111","c":"CN","rg":"","ci":"","tz":"Asia/Shanghai"}

-- 今日 PV：1 → 2
select key, value, expires_at from kv_strings where key='stats:pv:2026-09-23';
-- stats:pv:2026-09-23 | 2 | 2026-09-30T01:17:23Z      ← 注意：7 天后过期

-- 今日页面排行：出现新路径
select member, score from kv_zsets where key='stats:pages:2026-09-23';
-- /bugcheck-visitor-track.html | 1
-- /admin_Dx23.html?tab=visitors | 1

-- 今日 UV：2
select count(*) from kv_sets where key='stats:uv:2026-09-23';
```

**结论：写入链路（限流 → sadd/incr/zadd/lpush → Supabase）完全正常。**

### 2.2 时区错位的直接证据（B1）

`stats:recent` 里今天早上（CST 07:59）产生的两条记录：

```
idx=740  p="/activate.html"                t=1790121558777   ← CST 2026-09-23 07:59
idx=741  p="/activate.html?deviceId=Aa092" t=1790121580521
```

但这两条**没有**出现在 `stats:pages:2026-09-23`，而是出现在 **`stats:pages:2026-09-22`**：

```
stats:pages:2026-09-22  → /activate.html (3)、/activate.html?deviceId=Aa092 (2)、/admin_Dx23.html (2) …
stats:pages:2026-09-23  → 只有 /admin_Dx23.html?tab=visitors 和这次测试路径
stats:pv:2026-09-23 = 2      stats:pv:2026-09-22 = 17
```

原因：`api/activate.js` 的日期分桶用 **UTC**：

```js
// api/activate.js L40-46
function visitorTodayKey(ts) {
  var d = new Date(ts || Date.now());
  var y = d.getUTCFullYear();            // ← UTC
  var m = String(d.getUTCMonth() + 1).padStart(2, "0");
  var day = String(d.getUTCDate()).padStart(2, "0");
  return y + "-" + m + "-" + day;
}
```

而同一项目的限流模块用的是 **UTC+8**：

```js
// lib/rate-limit.js L48-58  getMinuteKey() 里 new Date(d.getTime() + (d.getTimezoneOffset() + 8*60) * 60000)
```

**后果**：北京时间 00:00–08:00 的所有访问，PV/UV/页面统计都会记到**前一天**的键里。
早上看后台「今日访客/PV」自然是 0 或极少 → 观感就是「写入没生效」。

### 2.3 地区字段全空（B2）

上面拿到的记录：`"c":"CN","rg":"","ci":""` —— 国家有值，**省/市为空**。
连后台自己产生的记录（`/admin_Dx23.html?tab=visitors`）也一样是空。

原因是 Vercel 的免费 geo 头部对**国内 IP**经常只给国家、不给省市：

```js
// api/activate.js L87-89
c:  req.headers["x-vercel-ip-country"] || "",          // "CN"
rg: req.headers["x-vercel-ip-country-region"] || "",   // ""
ci: req.headers["x-vercel-ip-city"] || "",             // ""
```

而同一个 IP 在 **`ip_lookups` 表**里其实有中文地理信息（由 ip-api `lang=zh-CN` 查得）：

```
ip=36.113.30.111  country=中国  region=浙江  city=杭州  sources=ip-api+ip-sb+ipinfo+ipwhois
```

**所以「地区为空」不是没查到，而是查到的数据没被用到**（两套 geo 数据源互不相通，见 B3）。

### 2.4 面板读的是另一套缓存（B3）

后台「访客记录」列表 `handleVisitorRecent2()`（`api/admin/health.js` L3015-3053）：

```js
var records = await redis.lrange("stats:recent", 0, 49);   // 明细
var obj = { ..., country: obj.c, region: obj.rg, city: obj.ci };   // ← Vercel 的空值
// 只从 ip:detail:<ip> 补 isp/org/asn/lat/lon（不补省市区）
```

实查 `ip:detail:*`：

```
键数量：7（很少）
值全部是英文：{"country":"China","region":"Shandong","city":"Qingdao", ...}
expires_at：全部为 null   ← 本该 24 小时过期，实际永不过期
```

两个问题：
1. **面板的省市来自 Vercel 空值**，`ip_lookups`（中文、35 行、永久）**完全没有被面板使用**；
2. `ip:detail:*` **没有 TTL**。原因：`lib/ip-lookup.js` 里写的是
   ```js
   await redisClient.set(cacheKey, ...);            // 未带 { ex: 24h }
   await redisClient.expire(cacheKey, IP_CACHE_TTL) // ← lib/redis.js 代理没有实现 expire（只有 pexpire）
   ```
   实查 `require('./lib/redis')` 的导出列表里有 `set` / `pexpire`，**没有 `expire`** → 这句会抛 `TypeError`，
   缓存既没设成 24h，也永远不会过期。所以面板上看到的是**很旧的英文地理信息**。

### 2.5 访客明细列表不是永久存储（B4）

```sql
select count(*)::int, min(idx), max(idx) from kv_lists where key='stats:recent';
-- 101 行, min_idx=498, max_idx=744
select column_name from information_schema.columns where table_name='kv_lists';
-- key, idx, value        ← 注意：没有 expires_at 列
```

- `lpush` 后紧跟 `ltrim(recentKey, 0, 99)` → **只留约 100 条**，老记录直接被删（实测 min_idx=498，说明已被裁掉两百多条）；
- `redis.pexpire("stats:recent", …)` 在代理里只 `UPDATE kv_strings`，对 `kv_lists` **毫无作用**（表里根本没这列）→ 写成「永久」，实际靠 ltrim 控量。

### 2.6 每日统计 7 天后消失（B5）

```sql
select key, value, expires_at from kv_strings where key like 'stats:pv:%' order by key desc limit 4;
-- stats:pv:2026-09-23 | 2  | 2026-09-30T01:17:23Z   ← 7 天
-- stats:pv:2026-09-22 | 17 | 2026-09-29T23:59:40Z
-- stats:pv:2026-09-21 | 10 | 2026-09-28T23:38:17Z
```

来源：`api/activate.js` L29 `var VISITOR_TTL = 7 * 24 * 60 * 60;`（PV/UV/页面排行都用它）。
`lib/redis.js get()`/`mget()` 会过滤 `expires_at < NOW()`，所以**7 天后历史数据在后台直接消失**（`purgeExpired()` 还会物理删除）。

### 2.7 两套埋点 + 埋点限流（B6）

| 入口 | 是否落库 | 作用 |
|---|---|---|
| `POST /api/admin/health?section=visit` | ❌ **不落库** | 只推 ev-notifier 通知（`pushToStream` 直连 Upstash） |
| `POST /api/activate?section=visitor-track` | ✅ 落库 | PV/UV/页面/`stats:recent` |

`activate.html` 等页面**两个都发**。排查时如果只看 `section=visit`，会以为「写入了但没数据」。

另外埋点有限流：`lib/rate-limit.js` `VISITOR_IP_MAX_HITS = 30`（30 次/分钟/IP），超了直接 **429 丢记录**；
公司/校园等共享出口 IP 会比较容易触发。

## 三、「是否写入 Supabase 永久保存」逐项核对

| 数据 | 落库位置（Supabase 表） | 写入入口 | 是否永久 |
|---|---|---|---|
| 访客明细（最近 ~100 条） | `kv_lists` → key `stats:recent` | `visitor-track` / `go.js` | ⚠️ 永久但**只留 ~100 条** |
| 每日 PV | `kv_strings` → `stats:pv:<UTC日期>` | `visitor-track` | ❌ **7 天过期** |
| 每日 UV（去重集合） | `kv_sets` → `stats:uv:<UTC日期>` | `visitor-track` | ❌ **7 天过期** |
| 每日页面排行 | `kv_zsets` → `stats:pages:<UTC日期>` | `visitor-track` / `go.js` | ❌ **7 天过期** |
| 点击明细（最近 ~40 条） | `kv_lists` → `stats:go:recent` | `go.js` | ⚠️ 只留部分 |
| IP 地理信息（中文） | **`ip_lookups`**（真实业务表，非 kv_*） | `ip-lookup` cron / 面板 | ✅ **永久**（`updated_at` 覆盖更新，无 TTL） |
| IP 地理缓存（面板用） | `kv_strings` → `ip:detail:<ip>` | `lib/ip-lookup.js` | ⚠️ 本应 24h，实际**永不过期且内容是旧的英文**（B3） |
| 通知消息流 | Upstash（非 Supabase） | `lib/notify.js` / `health.js` | Upstash 自身保留策略 |

**一句话**：**写进去了，但「永久保存」只有 `ip_lookups` 成立**；统计类数据 7 天、明细类只留 100 条。

## 四、修复建议

### P0（建议立刻修，1 行级改动）

| # | 改动 | 位置 | 说明 |
|---|---|---|---|
| F1 | 日期分桶改用 **UTC+8**（复用 `rateLimit.getMinuteKey()` 的时区算法） | `api/activate.js` `visitorTodayKey()` | 修掉「早上的访问记到昨天」，让「今日访客/今日 PV」正确 |
| F2 | `ip:detail` 缓存补 TTL：`set(key, val, { ex: 86400 })` 或给代理实现 `expire()` | `lib/ip-lookup.js`、`lib/redis.js` | 否则永远显示旧数据 |
| F3 | 面板读 geo 时**优先 `ip_lookups`（中文、永久）**，Vercel 头部仅兜底 | `api/admin/health.js` `handleVisitorRecent2` | 国内 IP 才有省市可显示 |

### P1

| # | 改动 | 说明 |
|---|---|---|
| F4 | 通知里的 `location_full_zh` 也优先用 `ip_lookups`/`geo-district` 的结果 | 与 F3 同源，能让通知出现「浙江杭州」 |
| F5 | `stats:recent` 的 TTL 语义澄清：要么承认「只留 100 条」，要么给 `kv_lists` 加 `expires_at` 并让 `pexpire` 生效 | 现在代码写了 `pexpire` 但实际无效，属于「假配置」 |
| F6 | 埋点限流独立并放宽（现有 `ratelimit:visitor:` 30/min，可提到 120/min）或超限改为「丢弃仍计数」 | 降低共享 IP 丢记录概率 |

### P2（如果要真正的「永久访客日志」）

| # | 改动 | 说明 |
|---|---|---|
| F7 | 新建业务表 `visitor_logs(id, ts, ip, path, ua, geo_zh, hash, source)`，`INSERT` 落库 | 不依赖 kv_* 结构，天然永久、可索引、可统计；`kv_lists` 的 100 条限制与 7 天 TTL 问题一次解决 |
| F8 | `stats:pv/uv/pages` 改为**先写 `visitor_logs`，统计用 SQL 聚合**（或保留 Redis 快照 + 每日归档到 Postgres） | 历史趋势不再 7 天后消失 |
| F9 | 埋点写库改为后台任务（`waitUntil`） | 不占用用户请求时间（同 `lib/geo-district.js` 的做法） |
