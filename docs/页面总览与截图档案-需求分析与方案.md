# 「页面总览 · 逐页截图档案」需求分析与方案

> 目标项目：`app-auth`（静态页 + Vercel 函数，线上 `app-auth.gudq.com`）
> 被扫描对象：手环端快应用 `guomengtao/class-schedule`（Ev课程表）
> 目标机型：**标准版手环 9（胶囊屏 192×490）**
> 文档状态：**方案待确认**（未开工）；成文 2026-09-27

---

## 一、需求原文与目标拆解

用户原话要点：

1. 在 app-auth 做一个**前台页面**，**用截图**给用户展示并讲解**每一个页面**
2. 面向**标准版手环 9 胶囊屏**用户
3. 顺便**核实每个页面是否有没有这些问题**（指近期修的"左小右大 / 文字被截断 / 热区"等）
4. **解锁后是否放在这个页面**？——目前还没激活高级版，需要分析
5. 是否**解释每个页面的简单用法**？页面是"用户手册"定位还是"效果展示"？
6. 页面要**明确注明版号 + 更新时间**
7. **核心目标：收集每个页面的截图，方便我们系统排查每个页面**

→ 拆成四件事：**① 截图画廊（核心） ② 逐页讲解 ③ 逐页体检结论 ④ 版本/时间可追溯**。

## 二、页面定位分析（先定这个，再谈实现）

### 2.1 已有页面都在做什么（避重）

| 现有页面 | 定位 | 与本案关系 |
|---|---|---|
| `ev-schedule.html`（1160 行） | 产品落地页/宣传 | 讲"好不好"，不讲"怎么用" |
| `course-guide.html` | 「Ev课程表 · 使用教程」 | 讲"怎么用"，**但按功能组织，不按页面组织** |
| `user-guide.html` | 「用户激活手册」 | 讲"怎么激活"，与页面无关 |
| `activate.html` | 激活入口 | 工具页 |

### 2.2 结论：定位 = **"逐页档案（排障索引）"为主，其他为辅**

> **一句话定位：这是一个"按页面组织"的档案库 —— 每个页面一张（或多张）截图 + 一句用途 + 条目要点 + 体检结论 + 版本时间。**

为什么不选另外两个：

- 纯"用户手册"：与 `course-guide.html` 重复，且用户手册按**任务**组织更合理（"我要加一节课"），按页面组织会很怪。
- 纯"效果展示"：那是落地页的活，且对排障毫无帮助。

**"按页面组织"的天然价值恰恰在排障**：用户说"我点设置就卡住"→ 我们能立刻定位到 `pages/settings` 的截图与已知问题；我们改完一版 → 对着档案逐页复检。

### 2.3 三级信息密度（一页之内同时服务三种人）

| 层级 | 内容 | 服务对象 |
|---|---|---|
| L1 一眼层 | 页面截图 + 中文名 + 分组 + 状态标签（正常 / 已知问题 / 高级版） | 用户、客服 |
| L2 一句话层 | 「这页是干嘛的」+ 入口路径（从哪进来）+ 3 条要点 | 新用户 |
| L3 排障层 | 体检结论（几何/截断/热区）+ 版本 + 截图时间 + 已知问题 | 我们（开发/排查） |

## 四、截图采集方案（这是本案的核心资产）

### 4.1 采集手段：已有工具直接复用

- 工具：`class-schedule/scripts/emulator-eye.js`（gRPC 直连 Vela 模拟器）
  可用命令：`shot` 截图、`ctap` 点击、`swipe` 滚动、`seq/sseq` 连点连截
- 环境：本机 VVD **`xiaomi_band`（192×490，adb emulator-5554，gRPC 8554）** —— 正好是标准版手环 9 规格
- 量测工具：`class-schedule/scripts/png-measure.js`（`runrow` 逐行色带）→ 用于**几何体检**（左右边距是否相等）

### 4.2 命名与存放约定

```
app-auth/images/ev-schedule/pages/<page-id>-<state>.png
例：pages/settings-list.png        pages/settings-theme-drawer.png
    pages/settings-unlock-modal.png  pages/index-empty.png
```

- 现成先例：`images/ev-schedule/` 已放 12 张（`hero-*` / `week-view-overview.png` …），**沿用同一目录风格**
- 命名一律小写 + 连字符；状态后缀固定几个词：`list` / `empty` / `modal` / `drawer` / `confirm` / `detail`

### 4.3 每个页面要"采得准"必须解决的三件事

1. **进入路径**：每个页面的入口（点哪里进）—— 建议建立 `通路表`（如 首页 →「设置」→ 设置页 →「首页设置」行）
2. **数据准备**：空态截图容易，**有数据态需要先注入**（课表/课程/昵称）。建议统一"演示数据脚本"（一次性写好，每轮采集前跑一遍）
3. **激活状态**：本页大量弹窗是"未解锁高级版"才出现的 → **未激活既是现状也是要展示的状态**，无需绕过（见第六节）

### 4.4 采集流程（建议固化为脚本 `scripts/capture-pages.sh`）

```
1. 部署当前手环端版本到 xiaomi_band（release 包；注意：模拟器只认解包目录，改单页只推 pages/<x>/<x>.jsc）
2. 注入演示数据
3. 按"通路表"逐页：ctap 进入 → shot 截图 → 需要弹窗的再 ctap → 再 shot
4. 输出到 images/ev-schedule/pages/，文件名带 page-id
5. 跑 png-measure runrow 做几何体检，结果写进 pages.json 的 check 字段
```

> ⚠️ 已知坑（本轮实测）：模拟器**只认解包目录**；批量 `adb push` 目录易 EOF（改单页只推单个 `.jsc`）；推送后首次启动可能黑屏，**再启动一次**即可。

## 六、高级版（解锁后）内容是否放在本页？—— 结论与理由

### 6.1 结论：**放，且必须放；但用"标签 + 解锁入口"而不是"隐藏"**

### 6.2 三个方案对比

| 方案 | 做法 | 优点 | 致命缺点 |
|---|---|---|---|
| A 隐藏 | 未解锁时高级版页面整块不显示 | 页面干净、有"想看得先解锁"的引导性 | **与本案核心目的冲突**：排障时看不到的页面 = 盲区；用户报"高级版某页有问题"，我们自己都打不开档案 |
| B 全放不标 | 所有页面一视同仁 | 简单 | 用户点进去发现"我没有这个功能"，观感差；也无法区分免费/付费边界 |
| **C 放 + 标注 + 入口（推荐）** | 全部页面都展示截图与说明；高级版页加 **「高级版」角标**，卡片底部给 **「未解锁 · 如何解锁」**；点进详情说明"解锁后可用、当前为演示截图" | 排障无盲区；顺便当付费引导；**未激活状态反而成为最好的"未解锁文案"展示位** | 需要一套"功能权限表"（哪些页/哪些功能属于高级版） |

### 6.3 需要维护的一张"权限对照表"（建议写进 `pages.json`）

```json
{ "id": "backup-restore", "premium": true,  "premiumNote": "云备份与恢复需解锁高级版" }
{ "id": "settings",       "premium": false, "premiumNote": "主题配色等 3 项需解锁" }
```

- 页面级：整页高级版（如 `backup-restore`、`statistics`）
- 功能级：页面免费但**部分功能**需解锁（`settings` 的主题、`homepage-settings` 的自定义、多课表）
- 现状（未激活）：**截图正好就是"未解锁弹窗"那一屏**，是当前最真实的状态，直接采即可；等有激活码后再补采一组"已解锁"截图，两组并排 = 最有说服力的对比

## 七、逐页体检清单（把近期踩的坑变成检查项）

近几轮实际修过的四类问题，建议**每一页都过一遍**并在 `pages.json` 记结论：

| # | 检查项 | 判定标准 | 实测方法 |
|---|---|---|---|
| 1 | **左右对称** | 卡片/抽屉左右边距**相等** | `png-measure runrow <y>`：卡片区间 `x=a..b` ⇒ 判 `a === (屏宽-1-b)` |
| 2 | **卡片宽度够** | 文本不被挤到换行成 3+ 行、标题不截断 | 同上 + 看图 |
| 3 | **文本不截断** | 标题/说明/条目末字不被吃掉；`lines` 值要够 | 看图；`.modal-desc` 建议 `lines: 4`（`lines: 2` 会吃掉"…高级功能"的末二字） |
| 4 | **热区够大** | 列表行整行可点（不是只有文字/圆圈） | 点行首、行尾空白各一次 |
| 5 | **底部安全区** | 内容不被胶囊屏圆角/底部裁切 | 看图 + 量 `y=480` 是否仍是面板内容 |
| 6 | **三屏型一致性** | 胶囊 / 方屏 / 圆屏 都看一遍 | 本机另有 336×480 方屏 VVD 可跑 |

**已知问题台账（本轮为止）**

| 页面 | 问题 | 状态 |
|---|---|---|
| `settings` 解锁弹窗 | 曾标题截成 3 字、✓ 条目只剩 1 字、右缘被裁 | ✅ 已修（16/16 对称） |
| `settings` 主题配色 | 原为页内展开、观感偏左 | ✅ 已改底部抽屉弹（通栏贴底） |
| `homepage-settings` 解锁弹窗 | 左 8 / 右 24；「✓ 数据备份与恢复」截断；说明末字被吃 | ✅ 已修（16/16、`lines:4`、条目 17px） |
| `backup-restore` 解锁弹窗 | 预计同样左 8 / 右 24（根容器 padding 未下移） | ⏳ **待修** |
| `reset-data` / `premium-overlay` | 待逐页核 | ⏳ 待核 |
| `schedule-manager` 弹窗 | 实测 8/8 已对称 | ✅ 通过 |
| `settings` 页面本身 | **不能滚动** → 192 屏上"首页设置/数据备份"等行**够不到** | ⏳ 待决策（建议加滚动容器） |

## 八、技术方案（必须遵守 app-auth 约束）

### 8.1 硬约束（引自项目长期约定）

- **单文件静态 HTML，无构建**；老 WebView：**只用 `var`、`XMLHttpRequest`**（可复用 `activate.html` 的 `xhrFetch()`）
- **禁** `fetch` / `const` / 箭头函数 / `IntersectionObserver`
- CSS 变量真名：`--bg` / `--surface` / `--card-bg` / `--ink` / `--muted` / `--line` / `--accent`（`--card` / `--text` **不存在**）
- 群号与联系方式**只允许写在页面底部静态 HTML**，不进 JS / `api/*`
- 部署：`./scripts/bump-version.sh` → **`git add <本次改动文件>`（含 `version.json`）** → commit → push（**禁 `git add -A`、禁 `scripts/push.sh`**）

### 8.2 文件清单（预计新增/改动）

| 文件 | 动作 | 说明 |
|---|---|---|
| `pages.html`（建议路径 `/pages`，用 `vercel.json` rewrite） | 新增 | 主页面（单文件） |
| `images/ev-schedule/pages/*.png` | 新增 | 27 页截图（首批约 25~30 张） |
| `pages.json` 或内联 `PAGES` 数据 | 新增 | 页面档案数据（id/名称/分组/用途/要点/premium/截图/check/版本/时间） |
| `version.json` | 改 | 按 `bump-version.sh` 自动 bump |

> 数据放**独立 `pages.json`** 更利于"只补采一页"时改数据不动页面；但老 WebView 需 `XMLHttpRequest` 拉取 → 若担心跨域/缓存，退一步把数据**内联**在 HTML 里（更省事、更稳），推荐**内联**。

### 8.3 页面结构（移动优先，因为用户多在手机上看）

```
[顶部固定] 标题 + v1.6.142(971) + 截图时间 + 页面更新时间
[筛选条]   全部 / 核心 / 课程 / 课表 / 设置  +  [只看有问题的]
[卡片流]   按分组手风琴
   └ 每个页面一张卡片：
        ┌───────────────┐
        │   截图（等比缩放到 192 宽的框架内，带"胶囊屏"外框）│
        └───────────────┘
        页面名（中文）  [高级版]  [已知问题 2]
        这页是干嘛的：一句话
        入口：首页 →「设置」→ …
        要点：·…  ·…  ·…
        体检：左右对称 ✅ / 文本完整 ✅ / 热区 ✅   （有问题则红色）
        截图 v1.6.142 · 2026-09-27 17:41
[底部静态] 加群/联系方式（静态 HTML）
```

### 8.4 交互（老 WebView 安全）

- 分组折叠：纯 DOM `classList` 切换（不用 `IntersectionObserver`）
- 截图点击放大：`onclick` 换 `src` 到大图 或 直接新开图（不做手势库）
- 筛选：`display:none/block` 切换
- **不要图片懒加载库**（`IntersectionObserver` 被禁）；截图多时用"分组默认折叠"控制首屏

## 十、验收标准

1. 打开 `/pages` 能一眼看到 **手环端版本 + 截图时间 + 页面更新时间** 三行
2. **27 页中至少核心 19 页**有截图，且截图规格标注为 **192×490（标准版手环 9）**
3. 每个页面卡片包含：截图 / 中文名 / 用途一句话 / 入口 / 要点 / 体检结论
4. 有问题的页面能在页面内**一眼筛出来**（红标 + "只看有问题的"筛选）
5. 高级版页面**可见但有明确标注**，且有"如何解锁"入口
6. 手机浏览器打开流畅（首屏 < 1s，老 WebView 不报错）
7. 页面底部为静态联系方式区（符合约定）

## 十一、风险与取舍
