# 跳转下载链接功能 · 方案设计

> 目标：把"爱发电购买地址"包成自己站点上的统计跳转链接，统计下载来源、渠道、设备等信息，再透明地跳到爱发电。
> 状态：**v1 已实现（2026-09-18）** · Q5 暂不区分 click vs purchase（按作者决策）
> 日期：2026-09-18

---

## 一、背景与目标

### 1.1 现状

| 现状 | 问题 |
|---|---|
| 给用户的是**爱发电的直接购买地址**（如 `https://afdian.com/a/xxx`） | 不知道用户从哪儿来、点了哪个按钮、用的什么渠道 |
| 唯一能统计的是爱发电侧（订单信息） | 无法与本站的设备、版本、渠道数据关联 |
| 各处推广位（官网、手册、教程页）散落多处链接 | 改链接要挨个改，无法集中管理 |

### 1.2 目标

1. **统计来源**：知道下载/购买链接的点击来自哪个渠道、哪个版本、哪个设备
2. **集中管理**：所有爱发电购买地址统一在一个地方配置，前端只引用"短链接"
3. **URL 隐藏**：用户看到的地址是自家域名下的短链，看不到真实的爱发电 URL
4. **参数容错**：上游传来的渠道/设备参数可能为空，必须能正常接收并记录（不报错）
5. **复用现有基建**：和 `activate.html` 一样使用同一套统计参数约定（`c/v/m/p/o/t/deviceId/...`）

### 1.3 非目标（本期不做）

- 不做用户身份绑定（无需登录）
- 不做归因模型（不区分"自然流量 vs 推广流量"）
- 不做防作弊（IP/UA 黑名单等）
- 不做可视化图表（仅提供原始数据 + 后台列表）

## 二、整体设计

### 2.1 核心思路

```
现在：  推广位 → https://afdian.com/a/xxx  → 用户购买
                                            ↑
                                       没统计

将来：  推广位 → https://app-auth.gudq.com/go/{slug}?c=...&v=...&deviceId=...
        → 服务端记录（渠道/版本/设备/UA/IP）
        → 302 重定向到配置的「爱发电 URL」
        → 用户购买
        ↑
   集中配置 + 完整归因
```

**关键点**：爱发电的购买 URL **不暴露在前端**，只存在服务端配置表里。前端永远只引自家的 `/go/{slug}`。

### 2.2 URL 设计

**对外的链接格式**（用户/前端看到的就是这个）：

```
https://app-auth.gudq.com/go/<slug>?<stats params>
```

示例：
```
https://app-auth.gudq.com/go/ev-timetable
https://app-auth.gudq.com/go/ev-timetable?c=t-9p-d
https://app-auth.gudq.com/go/ev-timetable?c=t-9p-d&v=1.6.0&deviceId=Aa09&m=Watch%20S4
https://app-auth.gudq.com/go/ev-timetable?c=t-9p-d&utm_source=doc&utm_campaign=2026q3
```

**slug 要求**：
- 英文、小写、连字符分隔（如 `ev-timetable`、`ev-schedule`、`monthly-card`）
- 与"下载 EV 课程表"等中文名一一对应
- 长度 3~50 字符
- 仅允许 `[a-z0-9-]`

## 三、跳转行为

### 3.1 服务端处理流程

```
请求 GET /go/<slug>?...
   │
   ├─ 1. 校验 slug 格式（正则），不合规 → 404
   │
   ├─ 2. 查 go:mapping:<slug> 配置
   │      ├─ 不存在 → 404（"链接不存在或已下线"）
   │      └─ 存在但 enabled=false → 410（"链接已下线"）
   │
   ├─ 3. 解析所有 stats 参数（缺省视为空字符串）
   │
   ├─ 4. 异步记录（不阻塞 302）：
   │      ├─ 计数器：stats:go:<date>  +1
   │      ├─ 分产品计数：stats:go:<date>:<slug>  +1
   │      └─ 最近列表：stats:go:recent  ← lpush 详细记录（ltrim 100）
   │
   ├─ 5. 设置响应头：
   │      ├─ Location: <配置中的爱发电 URL>
   │      ├─ Referrer-Policy: no-referrer    （不让爱发电知道我们的渠道）
   │      └─ Cache-Control: no-store          （不让中间层缓存跳转）
   │
   └─ 6. 返回 302
```

### 3.2 接受的 stats 参数（全部可选，缺失/空都允许）

参数名沿用 `activate.html` 已有的约定，方便复用：

| 参数 | 含义 | 示例 | 缺失时处理 |
|---|---|---|---|
| `c` | 渠道码（与 `activate.html` 一致） | `t-9p-d` | 记录为 `""` |
| `deviceId` | 设备ID | `Aa09` | 记录为 `""` |
| `m` | 设备型号 | `Watch S4` | 记录为 `""` |
| `p` | 产品 | `vela_ws4` | 记录为 `""` |
| `v` | 客户端版本 | `1.6.0` | 记录为 `""` |
| `o` | 操作系统版本 | `42` | 记录为 `""` |
| `t` | 设备类型 | `watch` | 记录为 `""` |
| `r` | ROM 版本 | `vela_1.5.70` | 记录为 `""` |
| `l` | 语言 | `zh-CN` | 记录为 `""` |
| `utm_source` | UTM 渠道 | `wechat` | 记录为 `""` |
| `utm_medium` | UTM 媒介 | `article` | 记录为 `""` |
| `utm_campaign` | UTM 活动 | `2026q3` | 记录为 `""` |
| `ref` | 推广人/推荐位 | `doc-link-3` | 记录为 `""` |

**前端构造时**：尽量传，缺也没关系。服务端**不校验**这些参数，只记录。

### 3.3 自动补充的字段（服务端自己取）

| 字段 | 来源 |
|---|---|
| IP | `req.headers["x-forwarded-for"]` / `x-real-ip` |
| UA | `req.headers["user-agent"]` |
| 国家/地区 | Vercel 头 `x-vercel-ip-country`、`x-vercel-ip-city` |
| 时间戳 | 服务端 `Date.now()` |
| Slug | URL 路径段 |

## 四、数据存储设计

### 4.1 链接配置

| Redis 键 | 类型 | 内容 |
|---|---|---|
| `go:mapping` | Hash | 字段名=slug，值=JSON 配置对象 |

单个配置 JSON：
```json
{
  "slug": "ev-timetable",
  "name_zh": "下载 EV 课程表",
  "name_en": "Download EV Timetable",
  "target_url": "https://afdian.com/a/ev-timetable",
  "enabled": true,
  "created_at": 1756646000000,
  "updated_at": 1756646000000,
  "note": "EV 课程表应用页购买链接"
}
```

> `target_url` 永不出现在前端源码、HTML、JS 文件中。

### 4.2 统计数据（参考 `activate.js` 的 `visitor-track`）

| Redis 键 | 类型 | TTL | 用途 |
|---|---|---|---|
| `stats:go:<YYYY-MM-DD>` | String | 7 天 | 当日总点击数 |
| `stats:go:<YYYY-MM-DD>:<slug>` | String | 7 天 | 当日各 slug 点击数 |
| `stats:go:<YYYY-MM-DD>:<slug>:channel` | Set | 7 天 | 当日各 slug 的渠道去重计数 |
| `stats:go:recent` | List（容量 100） | 7 天 | 最近 100 条点击详情 |

详情记录 JSON 字段：
```json
{
  "slug": "ev-timetable",
  "ts": 1756646000000,
  "ip": "1.2.3.4",
  "ua": "Mozilla/5.0...",
  "country": "CN",
  "city": "Shanghai",
  "params": {
    "c": "t-9p-d",
    "v": "1.6.0",
    "deviceId": "Aa09",
    "m": "Watch S4"
  }
}
```

> **容量控制**：`ltrim 0 99` 与现有 `stats:recent` 保持一致；超过 100 条自动丢老数据。

## 七、安全与隐私

| 风险 | 处理 |
|---|---|
| 爱发电 URL 通过 Referer 泄漏到第三方 | 跳转时设 `Referrer-Policy: no-referrer` |
| 爬虫/机器人刷量 | v1 **不做**；v2 加 UA 关键词黑名单 + IP 频次过滤 |
| 知道 slug 就能探测 `target_url` | 服务端查表，**不返回 target_url 给前端**；前端只发起请求，不读响应体 |
| 后台泄露目标 URL | 鉴权 + 角色控制（沿用现有 admin 鉴权） |
| 用户参数中含恶意字符 | slug 走严格正则；stats 参数**全部 `slice(0, N)` 截断**入库，防止 Redis 被塞爆 |
| 重定向循环 | v1 用静态字符串，不拼接参数；目标 URL 仅从配置读 |
| 用户隐私（IP/UA） | v1 记录到 Redis，仅后台可见；保留 7 天后过期 |

## 八、Vercel 路由配置

需要在 `vercel.json`（如有）或路由表中加一条 rewrite，让 `/go/<slug>` 实际命中 `/api/go`：

```json
{
  "rewrites": [
    { "source": "/go/:slug", "destination": "/api/go?slug=:slug" }
  ]
}
```

> 若项目没有 `vercel.json`，则改用单文件入口方案：所有 `/go/*` 路径在 Vercel function 端用一个 catch-all 文件 `api/go/[slug].js` 处理。

## 十一、已知限制与风险

1. **重定向目标 URL 仍可在服务端日志 / Redis 中查到**——管理员可看，非公开
2. **跨域跳转会丢失部分客户端信息**（如浏览器 locale），但我们已经记录在 stats 里
3. **短链接滥用**：任何人知道 slug 都能刷点击，v1 不防；上线后 1~2 周内加 bot 过滤
4. **爱发电改版后 URL 失效**：所有跳转都 302，不会出现 5xx 风暴
5. **后台权限沿用现有 admin 鉴权**：无新增角色；如需要"只读"角色，v2 再说
6. **不支持动态参数拼接**：目标 URL 是静态配置，不支持把 `?deviceId=...` 自动拼到爱发电 URL 上（如有需要 v2 加模板功能）
