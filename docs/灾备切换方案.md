## 场景一：Postgres 额度耗尽，切换到 Upstash

### 能否保证数据不丢失？

**关键问题：Postgres 额度耗尽后，还能读吗？**

Neon Postgres 免费版限制：
- 存储上限：0.5 GB
- 计算时间：190 小时/月
- **超出后行为：写入被拒绝，读取通常仍然可用**（取决于耗尽类型）

| 耗尽类型 | 读 | 写 | 能同步吗？ |
|---------|-----|-----|-----------|
| 存储满（0.5GB） | ✅ 可读 | ❌ 拒绝 | ✅ 可以同步 |
| 计算时间耗尽 | ❌ 暂停 | ❌ 暂停 | ❌ 不能同步 |
| 连接数耗尽 | ⚠️ 部分 | ⚠️ 部分 | ⚠️ 可能可以 |

### 保障措施

**1. 定时自动同步（推荐）**

在 `vercel.json` 添加定时任务，每 4 小时自动同步一次：

```json
{
  "crons": [
    {
      "path": "/api/admin/sync-to-upstash",
      "schedule": "0 */4 * * *"
    }
  ]
}
```

这样即使 Postgres 突然耗尽，Upstash 最多落后 4 小时数据。

**2. 额度预警**

Neon Dashboard 可设置用量告警。建议在存储使用达到 80% 时手动同步一次。

**3. 最坏情况**

如果 Postgres 完全不可读（计算时间耗尽），最后一次定时同步的数据就是你能恢复的全部数据。建议：

- 不要等到耗尽再同步，提前执行
- 重要操作后手动同步一次

### 操作步骤

```bash
# 1. 同步最新数据到 Upstash（如果 Postgres 还能读）
node scripts/backup-to-upstash.js

# 2. Vercel Dashboard → Settings → Environment Variables
#    添加 USE_UPSTASH=true

# 3. 重新部署
```

## 场景二：Upstash KV 额度耗尽，切回 Postgres

### 问题

Upstash KV 免费版限制：
- 存储：256 MB
- 每日请求：10,000 次
- **超出后行为：所有请求被拒绝（读和写都不可用）**

在 Upstash 运行期间，Postgres 可能已经恢复额度，但数据是旧的。

**关键问题：Upstash 运行期间产生的新数据，怎么同步回 Postgres？**

### 解决方案：反向同步

Upstash 只是备用方案，正常情况下不会运行太久。但如果确实在 Upstash 上运行了一段时间：

```bash
# 1. 从 Upstash 反向同步到 Postgres
node scripts/upstash-to-postgres.js

# 2. Vercel Dashboard → 删除 USE_UPSTASH 环境变量

# 3. 重新部署
```

### 反向同步的风险

| 风险 | 说明 | 处理 |
|------|------|------|
| 写入冲突 | Postgres 和 Upstash 都运行过，有相同 key | 反向同步用 `ON CONFLICT DO UPDATE`，Upstash 数据覆盖 Postgres |
| 数据丢失 | Postgres 有但 Upstash 没有的数据 | 取决于 Postgres 是否可读。如果可读，先同步 Postgres→Upstash，再 Upstash→Postgres 合并 |
| Upstash 不可读 | 请求次数耗尽，读也拒绝 | 无法同步，只能等额度恢复 |

## 场景三：Postgres 额度恢复，从 Upstash 切回

### 正常流程

```
Upstash 运行中（有新数据）
        │
        ▼
Postgres 额度恢复
        │
        ▼
执行反向同步：Upstash → Postgres
        │
        ▼
删除 USE_UPSTASH=true
        │
        ▼
重新部署，切回 Postgres
```

### 操作步骤

```bash
# 1. 确认 Postgres 可读写
#    Neon Dashboard 确认额度已恢复

# 2. 反向同步：Upstash → Postgres
node scripts/upstash-to-postgres.js

# 3. 验证 Postgres 数据完整性
#    登录后台，检查产品、兑换码、激活记录是否完整

# 4. 删除 USE_UPSTASH，重新部署
#    Vercel Dashboard → 删除 USE_UPSTASH=true → Redeploy
```

## 场景四：两边都耗尽

### 最坏情况

Postgres 和 Upstash KV 同时耗尽。系统无法运行。

### 恢复策略

1. 等待任一额度恢复（通常一个月重置）
2. 如果 Postgres 先恢复：
   - 数据可能已过期，但可恢复运行
   - 丢失 Upstash 运行期间的数据（如果 Upstash 不可读）
3. 如果 Upstash 先恢复：
   - 反向同步回 Postgres
   - 切回 Postgres 运行

### 日常维护

| 频率 | 操作 | 命令 |
|------|------|------|
| 每天 | 检查 Postgres 用量 | Neon Dashboard |

| 步骤 | 操作 | 预计耗时 |
|------|------|---------|
| 1 | Postgres 耗尽，手工同步最新数据 | 3 秒 |
| 2 | 设置 `USE_UPSTASH=true` | 30 秒 |
| 3 | 重新部署 | 30 秒 |
| **总计** | | **约 1 分钟** |

| 步骤 | 操作 | 预计耗时 |
|------|------|---------|
| 1 | 确认 Postgres 额度恢复 | - |
| 2 | 反向同步 Upstash→Postgres | 5 秒 |
| 3 | 删除 `USE_UPSTASH` | 30 秒 |
| 4 | 重新部署 | 30 秒 |
| **总计** | | **约 1 分钟** |
