# 帮助与反馈栏目方案

> 日期：2026-10-01。目标站点：https://app-auth.gudq.com/（本仓库，静态 HTML + Vercel Serverless + Postgres/Upstash Redis）。
> 覆盖三平台：网站 / 手环 EV 课程表（快应用）/ 手机 App 同步器（APK）。

---

## 0. 命名决策（先定名）

| 候选 | 评价 |
|------|------|
| 反馈 | 只有"提交"没有"自助解决"，偏窄 |
| 帮助 | 只有"看"没有"说"，偏窄 |
| 反馈帮助 | 生造词，别扭 |
| **帮助与反馈** ✓ | 微信/MIUI 惯例，覆盖"自助查 + 提意见"双向，用户零学习成本 |

**定名：帮助与反馈**；导航短标签「反馈」；URL `/feedback.html`；
手环菜单项「帮助与反馈」；同步器设置项「帮助与反馈」。
口头引导统一一句话："有问题去官网反馈页"。

## 2. ① 动态最新版提示

**解决**："你遇到的问题新版已经修了，但你还在用旧版"——最高频的无效反馈。

- 后端：新增 `GET /api/feedback/version`，聚合三平台最新版本（数据源沿用现有机制：
  同步器读 `dist/update-<variant>.json`，快应用读 `version.json`/渠道包名），返回
  `{ watch: "1.7.7", apk: "0.5.102", notes: "修复动画页黑屏…" }`
- 前端：页面加载后比对 URL 参数里的用户版本（见 §3 追踪），旧 → 显示提示条：
  「检测到你的版本 v1.7.6 不是最新（最新 v1.7.7：修复加载动画黑屏）→ [获取最新版]」
- 新版说明文案随包发布维护（放进 version 聚合接口，一处更新三端展示）

## 3. 扫码追踪（手环 → 网站带参）

**解决**："收到反馈不知道用户用的哪版/哪机型/哪渠道"。

- URL 格式：`https://app-auth.gudq.com/feedback.html?src=watch&v=1.7.7&m=Band9Pro&ch=t-9p-d`
  - `src`：watch / app / web；`v`：应用版本；`m`：机型；`ch`：渠道
- 手环端：设置 → 帮助与反馈 → 显示二维码（快应用 canvas 用轻量 QR 生成器 ~3KB，
  纯 JS 无依赖）+ 二维码下显示一行小字"扫码进入反馈页"
- App 同步器：设置 → 帮助与反馈 → 直接 Intent 打开浏览器带参 URL
  （复用现有 UpdateChecker 的版本/渠道常量，参数现成）
- 落库：feedback 提交时带上 URL 参数 + `visitor_logs`（现有全站埋点）自动记 UV/PV
- **向下兼容（硬要求）**：现有后台追踪已比较完善，反馈追踪**不另起炉灶**——
  参数名对齐现有埋点字段、写入同一条 visitor_logs 链路；
  旧版页面/旧版 App 提交时**参数全部可选**（缺省 src=web、版本=unknown），
  后端对缺参完全容忍；追踪表结构只加列不加改，旧数据零影响
- **降级**：二维码在低版本快应用上绘制失败 → 显示短链文本（可复制的明码参数 URL）

## 4. ② 常见问题 FAQ（快速自助）

先自助后留言，直接消化掉高频重复反馈。首批条目（含你点名的）：

| 问题 | 状态/答案 |
|------|----------|
| 退不出去 / 退不出应用 | ✅ 已解决：新版首页有退出按钮，更新即可 |
| 输入法显示不全 / 无法使用 | workaround：横竖屏/缩小字号；已列入修复计划 |
| 界面显示问题（错位/黑块） | 引导带截图留言（自动带版本参数） |
| 字号问题（太大/太小） | 指引现有字号设置项；收集诉求定上限档位 |
| 激活码无效/提示错误 | 指引激活指南页 + 自助查询接口 |
| 手环连不上 / 连接失败 | 指引 Band 页重连 + 省电白名单引导 |
| 课表不同步 / 慢 | 检查小米运动健康版本 + 后台限制 |
| 上课提醒不响 | 提醒权限 + 精确闹钟授权指引 |
| 桌面插件不刷新 | 插件刷新机制说明 + 手动刷新方法 |
| 课表数据丢失 | 多课表机制说明 + 手环端仍有的提示 |

FAQ 数据放 `data/faq.json`，前后端共用；后台可增改（见 §7），改完不用发版。

## 6. ④ 留言板

### 6.1 编辑器选型（粘贴图片是核心需求）

| 方案 | 体积 | 粘贴图片 | 评价 |
|------|------|---------|------|
| **自写 textarea + paste/drop 事件** ✓ | 0（~80 行） | ✓ 原生事件拿 clipboardData.files | 最贴本项目手写风格；用户是普通用户，Markdown 语法反而是门槛 |
| Vditor（wysiwyg 模式） | ~200KB | ✓ | 功能全但重，CDN 依赖 |
| EasyMDE | ~150KB | 需另配上传 | 纯 Markdown 语法，对小白不友好 |

**推荐：自写 textarea + 图片粘贴/拖拽**。Markdown 不作为用户必需——
内容按纯文本存，展示时做极简渲染（换行/缩进保留）；不引编辑器库。
（如果后续要 Markdown，Vditor 是首选，留作二期。）

- 图片：粘贴或拖拽/选图 → 前端 canvas 压缩为 webp（**≤960px、质量 70、目标 ≤80KB/张，
  硬上限 150KB，服务端超限拒绝**——"够看清问题即可"，节约存储）→
  最多 3 张 → 上传 `POST /api/feedback/upload` → **Vercel Blob** 存图（新增依赖，
  免费额度够用），返回 URL；预览缩略图可点开原图
- 截图在手机上同样成立：同步器反馈入口可带"从相册选截图"（二期，网页上传已够用）

### 6.2 后端（复用现有基建）

```
POST /api/feedback          # 提交留言（限流：lib/rate-limit，同 IP 5 条/天）
POST /api/feedback/upload   # 传图（限流 10 张/天/IP，鉴权同上）
GET  /api/admin/feedback    # 后台列表（挂进现有 admin 鉴权）
PUT  /api/admin/feedback    # 状态流转：新→处理中→已解决/不予处理
```

- 存储（Postgres 新表）：
  `feedback(id, created_at, src, app_version, device_model, channel,
  type, content, contact_type, contact, images[], status, admin_note)`
- 反滥用：限流 + 隐藏蜜罐字段 + 内容长度上限 2000 字 + 图片数/大小上限；
  不上验证码（降低提交门槛）
- 通知：新留言走现有 `lib/notify` 推给你（与现有通知管道一致）

### 6.3 联系方式与回复闭环

- 联系方式**选填、可匿名**：QQ / 邮箱 / 手机 三选一，单选输入 + "匿名提交"勾选
- 文案：「需要回复请留联系方式；想和大家讨论，推荐加入 QQ 群（上方群卡片）」
- 隐私小字：联系方式仅用于回复本次反馈，不公开、不用于其他用途
- 回复闭环：后台标注"已解决/已回复"后，留言状态反映到网站
  「已知问题与修复记录」区（公开的 changelog 式列表），让用户看到反馈被处理——
  这是提升信任、减少重复反馈的关键

## 10. 风险与边界

| 风险 | 应对 |
|------|------|
| 留言垃圾/刷接口 | 限流 + 蜜罐 + 长度/张数上限；不上验证码 |
| 截图含个人信息 | 提交前明确提示"截图将随反馈上传，请自行遮挡隐私" |
| QQ 群二维码过期 | 用官方加群链接生成，不用会过期的群二维码 |
| Vercel Blob 超额 | 图片压缩上限 200KB×3 张/条 + 后台可删图 |
| 手环低版本画不出二维码 | 明文短链兜底 |
| 匿名滥用无法回复 | 提交前提示"匿名将无法获得回复"；QQ 群兜底 |
