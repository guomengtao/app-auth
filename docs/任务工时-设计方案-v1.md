## 一、目标与边界

**目标**：给每个任务（进行中/已完成）显示"用了多长时间"，且**作为工作效率指标必须防虚高**——烂尾任务（开发到一半不回来登记/忘记关单）的墙钟时间不能算有效工时。

**核心问题（用户点名）**：任务挂着不开、忘关、烂尾 → 墙钟时间虚高 → 效率指标失真。必须有**多维度控制手段**兜底。

**边界（不做）**：
- 不做人工打卡/timer UI（工时全部自动推导）；
- 零 Supabase schema 变更（closed_at 写进已有 extra jsonb，工时实时派生）；
- 不改活跃度四档位（工时是活跃度之上的派生维度）。

## 二、侦察结论（已有证据链）

| 证据 | 位置 | 用途 |
|---|---|---|
| `created_at` / `updated_at` | evops_tasks | 墙钟口径的起点；close 时刻可用 updated_at 近似（有偏差，见 #2 改动） |
| 会话 `started_at` → `heartbeat_at` | evops_sessions | 心跳窗口 = 真实"在场"证据 |
| 会话黑板 `tasks[].prompts[]`（带时间戳、max 20） | session-sync 上报 | **最硬证据**：每次 prompt 的时刻 → 可精确切片出"活跃会话"区间 |
| ev-edit-stats 钩子累加 `adds/dels/file_count/last_prompt` | session tasks[] 统计 | 编辑证据：有代码改动 ≠ 纯挂机 |
| `taskActivity()` 四档位 | ev.js（本日已上线） | orphan/unbound 直接复用为"停表"判定 |
| task-close 时 extra 可写 | handleTaskClose | 落 `closed_at` 的零 schema 入口 |

## 三、工时定义（三口径 + 一置信度，防虚高是灵魂）

| 口径 | 计算 | 用途 |
|---|---|---|
| ⏱ **wall_min**（墙钟） | (closed_at ‖ now) − created_at | 参考值：挂机/烂尾会虚高，**不进效率指标** |
| ✅ **active_min**（有效工时，**主指标**） | 心跳切片法：会话在任务绑定期间的 `started_at→heartbeat_at` 窗口内，**掐头去尾**——单次 idle 间隔 > `EV_EFF_GAP_MIN`（默认 30min）的只计 30min（经典 time-tracking 规则）；窗口与 orphan 判定联动：**任务转 orphan 即停表**，工时冻结在最后一次心跳 | 效率指标唯一口径 |
| 🔍 **evidenced_min**（证据工时） | per-prompt 轨迹切片：相邻 prompt 间隔 ≤ gap 计入，> gap 只计 gap 上限；无 prompt 轨迹时用 last_prompt + adds/dels>0 兜底为"≥1 个活跃切片" | 交叉验证 active_min，防"心跳活着但人在摸鱼" |
| 📊 **confidence** | high：有 prompt 轨迹且 active≥evidenced×0.5；mid：有编辑证据；low：仅心跳、或 unbound（无会话=工时不可信，置 0 并标 `unbound`） | 消费方（面板/周报）按置信度加权 |

**防虚高四道闸**（多维度控制手段）：
1. **停表闸**：`taskActivity` 判 orphan/unbound → 工时冻结（`frozen: true` + `frozen_at`），不再累积；
2. **gap 闸**：任意两次活跃证据间隔 > 30min（可调 `EV_EFF_GAP_MIN`），超出部分不计——上厕所/吃饭/隔夜不计时；
3. **closed_at 闸**：task-close 当场把 `closed_at` 写入 `extra.closed_at`（jsonb，零 schema 变更）——墙钟口径的终点从此精确，不再靠 updated_at 猜；
4. **大限闸**：in_progress 超 `EV_EFF_CAP_DAYS`（默认 7 天）且无近期证据 → active_min 封顶为"最后活跃日之前的累计"，并在响应里标 `capped: true` 提醒人工复核。
