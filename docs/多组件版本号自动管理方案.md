# 多组件版本号自动管理方案 — 需求分析与实施评估

## 一、需求背景

用户提出：**网站后台、ev-notifier、工具（如课程表同步器）等各个组件都应有独立版本号，且每次改动后 patch 位（第三位）自动 +1**，例如 1.2.3 → 1.2.4。

核心目的：
- 方便团队成员交流进度（"你用的是 ev-notifier v2.3.5 吗？"）
- 明确的版本追溯，知道哪个版本修复了什么问题
- 避免手动改版本号忘记更新导致的版本混乱

---

| **ev-schedule-sync** | `manifest.json` 的 `"version"` 字段 | `1.0.0` | ❌ 手动修改 | 有版本字段，但无自动递增机制 |

## 三、需求评估：是否合适？

### 3.1 ✅ 合适的理由

| 角度 | 分析 |
|------|------|
| **多组件独立演进** | ev-notifier 和主站的发布节奏完全不同，独立版本号是合理的 |
| **历史版本追溯** | ev-notifier 已有 `ev_notifier_v1.0.1.py` ~ `v1.5.0.py` 的历史版本归档，版本号对这个组件非常有价值 |
| **交流效率** | "ev-notifier v2.3.5 有个 bug" 比 "最近那个版本的 ev-notifier 有问题" 精确得多 |
| **变更追踪** | 每次改动都留下版本记录，出问题时可以快速定位到引入问题的版本 |
| **工作量小** | 每个组件只需一个 `version.json` + 自动化脚本，成本极低 |

### 3.2 ⚠️ 潜在问题

| 问题 | 严重程度 | 对策 |
|------|---------|------|
| 多个版本号可能造成混淆 | 低 | 各组件版本号独立命名空间，互不干扰 |
| 同一个 commit 改了多个组件，版本号都要 bump | 中 | 用「改动检测」机制：只 bump 有文件变更的组件 |
| 自动化脚本可能 bump 了不该 bump 的组件 | 低 | 基于 git diff 检测变更目录，精确只 bump 有改动的组件 |
| ev-notifier 版本号在 Python 代码里硬编码 | 中 | 改为从 `version.json` 读取，保持单一数据源 |

### 3.3 结论：**非常合适，建议实施**

这个需求投入产出比极高。唯一需要注意的是「多组件改动的版本 bump 粒度」问题，下面详细设计方案。

## 四、实施难度评估

### 4.1 总体评估：**低难度** ⭐

| 任务 | 难度 | 预计工作量 |
|------|------|-----------|
| 为 ev-notifier 创建 `version.json` | 低 | 5 分钟 |
| 修改 `ev_notifier.py` 从 `version.json` 读取版本 | 低 | 10 分钟 |
| 创建统一 bump 脚本（检测变更组件） | 中 | 30 分钟 |
| 更新 `push.sh` 集成多组件 bump | 低 | 10 分钟 |
| 为 ev-schedule-sync 添加 bump 支持 | 低 | 10 分钟 |
| 更新项目规则文档 | 低 | 5 分钟 |

**总计约 1 小时**，无技术障碍。

### 4.2 唯一的技术挑战

**同一个 commit 改了多个组件的文件时**，应该如何 bump？

例如：改了 `api/activate.js`（主项目）和 `tools/ev-notifier/ev_notifier.py`（ev-notifier），应该 bump 几个版本？

**推荐方案**：**基于目录的改动检测**，每个有实际变更的组件各自 bump 自己的版本号。这样最精确，不会出现"主站改了但 ev-notifier 也被强制 bump"的情况。

```
git diff --name-only HEAD~1 检测到：
  api/activate.js              → 主项目有改动 → bump version.json
  tools/ev-notifier/ev_notifier.py → ev-notifier 有改动 → bump tools/ev-notifier/version.json
  tools/ev-schedule-sync/src/lib.rs → sync 有改动 → bump manifest.json
```

## 五、推荐方案：多组件自动 bump 机制

### 5.1 版本文件布局

```
app-auth/
├── version.json                              # 主项目版本（已存在）
│
├── tools/
│   ├── ev-notifier/
│   │   ├── version.json                      # 新增：ev-notifier 版本
│   │   └── ev_notifier.py                    # 改为从 version.json 读取 VERSION
│   │
│   └── ev-schedule-sync/
│       └── astrobox-build/astrobox-plugin/
│           └── manifest.json                 # 已存在：sync 版本
│
└── scripts/
    ├── bump-version.sh                       # 改造：统一 bump 脚本
    └── push.sh                               # 改造：集成多组件 bump
```

### 5.2 核心脚本逻辑

`scripts/bump-version.sh` 改造为：

```bash
#!/bin/bash
# 检测 git 变更的组件目录，自动 bump 对应版本号
#
# 组件 → 版本文件 映射表：
#   api/* server/* admin_*   → version.json
#   tools/ev-notifier/*      → tools/ev-notifier/version.json
#   tools/ev-schedule-sync/* → tools/ev-schedule-sync/.../manifest.json
```

**改动检测逻辑**：

1. 获取 git 暂存区 + 工作区的所有变更文件列表
2. 按路径前缀匹配组件
3. 对匹配到的每个组件，递增其版本文件的 patch 位
4. 输出 bump 结果汇总

### 5.3 版本号格式

统一采用语义化版本 `major.minor.patch`：

| 版本位 | 含义 | 递增方式 |
|--------|------|---------|
| major（主版本） | 架构级变更 | **手动修改** |
| minor（次版本） | 功能新增/重要改进 | **手动修改** |
| patch（修订版本） | Bug 修复/小改动 | **自动 +1** |

自动 bump 只针对 patch 位，major 和 minor 由开发者手动修改。

### 5.4 ev-notifier 版本号读取改造

当前 `ev_notifier.py` 中版本号硬编码：

```python
VERSION = "v2.3.5"
```

改造为从 `version.json` 读取：

```python
import os, json

_VERSION_FILE = os.path.join(os.path.dirname(os.path.abspath(__file__)), "version.json")

def _load_version():
    try:
        with open(_VERSION_FILE, "r") as f:
            return "v" + json.load(f)["version"]
    except Exception:
        return "v0.0.0"

VERSION = _load_version()
```

好处：
- 版本号与代码分离，bump 脚本不需要修改 Python 代码
- `version.json` 是唯一数据源
- `ev_notifier.py` 文件本身不用在每次 bump 时被修改

## 六、自动化程度分析

### 6.1 当前方案

```
开发者 → 手动改版本号 → git commit → git push
         ⚠️ 容易忘记
```

### 6.2 推荐方案

```
开发者 → git add → ./scripts/push.sh "提交信息"
                    ↓
                    bump-version.sh（自动）
                    ├─ 检测哪些组件有改动
                    ├─ 只 bump 有改动的组件版本号
                    └─ 输出 bump 汇总
                    ↓
                    git add -A（含 bump 后的版本文件）
                    git commit
                    git push
         ✅ 不会忘记
```

### 6.3 更进一步：Git Pre-commit Hook

如果希望**完全不依赖记忆**，可以加一个 Git pre-commit hook：

```bash
# .git/hooks/pre-commit
# 每次 commit 前自动检测变更并 bump
```

但 **不推荐**这么做，原因：
1. pre-commit hook 是本地配置，不会被 git 跟踪，换机器就失效
2. 有时候只想 commit 不改版本号（如文档修改、WIP 提交）
3. 会让 commit 操作变慢

**推荐保持 `push.sh` 方式**，它已经是一个好习惯，只需扩展支持多组件即可。
