# 米坛运营「批量导入奖品后丢失」修复报告

- 日期：2026-10-07
- 级别：**L3**（触及奖品发放/展示链路）→ 实为**前端展示缺陷 + 部署缺口**，未改后端逻辑
- 类型：线上紧急止血（当天补写本报告）
- 影响范围：`ev/app-auth` 管理页「米坛运营 → 奖品池」Tab

## 一、现象（用户报告）

> 批量导入奖品后，奖品「丢失」——导入提示成功，但列表里看不到。

## 二、根因（线上实测，非推测）

| 探测 | 线上返回 | 结论 |
|---|---|---|
| `op=reward-pool-stats` | `{"total":22,"assigned":0,"claimed":0,"remaining":22}` | **22 个奖品全在，一个没丢** |
| `op=reward-pool-list` | `{"success":false,"error":"unknown op: reward-pool-list"}` | **批次 4 后端未部署** |

**数据没丢，是「静默降级」把未发放奖品藏起来了**：

1. 前端 `loadRewardPool()` 先请求 `op=reward-pool-list`（全量，含未发放）。
2. 线上该 op 不存在 → 返回 `success:false` → 前端**不报错、静默** fallback 到 `op=reward-log`。
3. 而后端 `getRewardLog` 第 721 行 `if (!entry.assigned) continue;` —— **只回「已发放」**。
4. 刚导入的奖品 `assigned:false` 全部被过滤 → 列表显示「暂无发放记录」→ 用户看到的就是「导入后丢失」。

### 叠加缺陷（独立触发，同一症状）

`importRewardLinks()` 导入成功后只调 `loadPoolStats()` + `loadRewardLog()`（旧的、只含已发放），**没调 `loadRewardPool()`** → 即使后端正常，导入完立刻也被覆盖成「暂无发放记录」。

## 三、修复（单文件 `admin-bandbbs.js`，6 处）

| # | 位置 | 改动 |
|---|---|---|
| P1 | `importRewardLinks()` 成功回调 | `loadRewardLog()` → **`loadRewardPool()`**（全量刷新，含未发放） |
| P2 | `loadRewardLog()` | 删除（已无调用点，且会用只含已发放的数据覆盖同一容器） |
| P3/P4 | `loadRewardPool()` 降级分支 | 打 `degraded` 标记；降级时补拉 `reward-pool-stats` 取真实 `total` |
| P5 | `loadRewardPool()` 收尾 | 记录 `window._bbPoolDegraded` |
| P6 | `updatePoolAlert()` | 降级时显式告警：**「仅显示已发放」+「奖品池实际共 N 条」+「数据仍在库中，未丢失」**，并把统计卡 total 修正为真实值 |

P2 首轮实现有缺陷（按区间切片误删了夹在中间的 `bbPoolState`／`bbNormalizePoolItem`／`bbPoolCountsLocal`），已通过**花括号配平精切**重做并加断言防复发。
