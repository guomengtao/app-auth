## 一、现状诊断（为什么"乱"）

对线上 headless 渲染图与源码逐块核对，问题不是"配色不好看"，而是**信息架构与设计系统双重缺失**：

| # | 问题 | 具体表现 | 后果 |
|---|---|---|---|
| 1 | 单一顶栏超载 | 标题、副标题、下载按钮、版本 chip、截图时间、页面更新时间全塞进一条 sticky bar，还挂了**两排** pill 按钮（紫色筛选 + 蓝色全站导航） | 首屏没有视觉焦点，两组导航颜色互相打架 |
| 2 | 缺少层级 | H1 与卡片标题字号差仅 0.2rem，所有区块都是白底圆角卡、同等权重 | 用户不知道先看哪里 |
| 3 | 提示条抢戏 | 黄色高饱和 banner 独占一整行长句；宣传图带下面又跟一条黄色 disclaimer | 全页两处黄色告警，但实际没有告警内容 |
| 4 | 卡片形态错误 | 16 页用「左侧 340px 高手机图 + 右侧文字」横排，右侧 4 个要点 + 3 行 meta 稀疏留白 | 一屏只放得下 1–2 张卡，整页要滚十几屏 |
| 5 | 分组零碎 | 6 个分组中「工具箱」只有 1 页、「课程」2 页，组标题与卡片标题争夺注意力 | 扫描成本高 |
| 6 | 装饰性噪音 | 绿色/灰色徽标、虚线分隔的 meta、项目符号列表、每组可折叠箭头 | 同一屏出现 5 种以上视觉语汇 |
| 7 | 组件无规范 | 圆角 12/14/16/17/20/22 混用，间距 2/4/6/8/10/12/14/18 混用，紫色与黄色无语义关联 | 无法维护、无法扩展 |

**核心判断**：这是一个「截图档案 / 排障索引」，主任务是**快速找到某一页并看清它**，不是阅读长文。当前设计把每页的完整说明都摊开，等于把索引做成了文档。

## 二、设计目标

1. **一屏定位**：3 秒内能看清「这是什么、什么版本、去哪下载、有多少页」。
2. **扫描优先**：16 页以紧凑网格呈现，桌面一屏 4 张，全页 4 行结束。
3. **细节按需**：用途/入口/要点收进点击后的详情面板，不再常驻占位。
4. **单一主色 + 中性骨架**：去掉黄色告警与蓝色 pill，颜色只承担「主行动 / 新版 / 旧版」三种语义。
5. **不破坏既有工程接线**：补采脚本、评分组件、全站导航、埋点全部保持可用。

## 三、信息架构（重构后）

```
┌ Hero：eyebrow → H1 → 一句话定位 → 主 CTA(下载 APK) / 次 CTA(采集说明)
│        右侧：版本主视觉（v0.6.56 · code 238）
├ Metric 条：16 页实拍 / 12 页 v0.6.56 / 4 页 v0.6.8 / 更新 2026-11-12

├ 界面速览：3 张宣传裁切图等宽横排 + 一行中性说明（可点放大）
├ ── 截图档案 ──────────────────────────────
│   分区导航（sticky 单行）：全部 16 / 核心界面 4 / 课程管理 4 /
│                            手环与个性化 3 / 工具与支持 5
│   ┌ Section：核心界面 ───────────── 4 页
│   │   [卡片网格 4 列] 缩略图 · 名称 · 一句话用途 · 版本徽标
│   ├ Section：课程管理 ───────────── 4 页
│   ├ Section：手环与个性化 ───────── 3 页
│   └ Section：工具与支持 ─────────── 5 页
├ 采集信息：双批次口径（结构化定义列表，弱化）
└ Footer
```

**分区映射**（不修改 `DATA.pages[].group` 原值，仅在渲染层归类）：

| 分区 | 包含 group | 页数 |
|---|---|---|
| 核心界面 | 底栏 4 页 | 4 |
| 课程管理 | 导入导出、课程 | 4 |
| 手环与个性化 | 留言与个性化 | 3 |

## 四、设计系统（Design Tokens）

| Token | 值 | 用途 | 对比度 |
|---|---|---|---|
| `--brand-50` | `#f2f1ff` | 主色浅底、选中态 | — |

| `--ink-500` | `#5f6577` | 次要文字 | **6.0:1** ✅ |

| `--surface` | `#ffffff` | 卡片 | — |
| `--ok-50 / --ok-700` | `#e9f8f0` / `#116b3f` | 新版实拍徽标 | **6.1:1** ✅ |
| `--slate-100 / --slate-600` | `#f1f3f7` / `#525a6b` | 旧版存档徽标 | **6.4:1** ✅ |

> 移除所有告警黄（`#fff7e0` / `#f0dfa8`）与蓝色 pill；提示条改用 `--brand-50` 中性信息底。

### 字阶 / 行高

`12 / 13 / 14 / 16 / 18 / 22 / 28 / 36 / 44 px`；正文 1.65，标题 1.25。
字体：`-apple-system, "PingFang SC", "Noto Sans SC", system-ui, sans-serif`；数字用 `font-variant-numeric: tabular-nums`。

### 间距（8pt 基准，仅用这 8 档）

`4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 px`

### 圆角 / 阴影 / 动效

- 圆角：`8`（徽标/小控件）、`12`（按钮/输入框）、`16`（卡片）、`20`（大容器）、`999`（pill）
- 阴影：`sm 0 1px 2px rgba(20,23,43,.05)`、`md 0 6px 20px rgba(20,23,43,.08)`、`lg 0 18px 48px rgba(20,23,43,.16)`
- 动效：`150ms ease`（hover/focus）、`240ms ease`（卡片位移/灯箱）；统一 `prefers-reduced-motion: reduce` 时归零

## 五、组件规范

| 组件 | 规格 |
|---|---|
| `.btn-primary` | 高 44px、圆角 12、brand-600 实心白字、hover brand-700 + `translateY(-1px)` + shadow-md；`focus-visible` 2px outline offset 3px |
| `.btn-ghost` | 同高、透明底、1px `--line`、ink-700 文字 |
| `.badge-new` / `.badge-legacy` | 高 22px、圆角 999、12px/700、语义色对；不用图标避免噪音 |
| `.shot-card` | 白底、1px line、radius 16、overflow hidden、hover shadow-md + 轻微上浮；**整卡可聚焦可点击**（`tabindex=0` + Enter/Space） |
| `.shot-frame` | 中性浅灰底（非黑框）、居中手机缩略图、固定高 300px、`object-fit:contain`、内边距 16px；黑框改为细边框 + 圆角，降低视觉重量 |
| `.section-head` | 左侧 3px brand-600 竖条 + 20px 标题 + 一行灰说明；右侧页数计数 |
| `.seg-nav` | sticky 单行、横向可滚动、 pills 用 brand-50 选中态；同时承担筛选 |
| `.dialog` | `role="dialog" aria-modal="true"`、遮罩 `rgba(12,14,28,.72)`、左右分栏、Esc 关闭、打开时锁 body 滚动、关闭后焦点回原卡片 |
| `.metric` | 数字 28px/700 + 标签 12px/500，无边框浅底，四项等宽 |

### 响应式

| 断点 | 网格 | 说明 |
|---|---|---|
| ≥1200px | 4 列 | 容器 1200px |
| 900–1199px | 3 列 | Hero 仍双栏 |
| 640–899px | 2 列 | Hero 单栏、指标 2×2 |
| <640px | 2 列（缩略图高 230px） | 灯箱改为上下堆叠、导航横滚 |

### 无障碍（WCAG AA 基线）

- 所有文本组合 ≥ 4.5:1（大号 ≥ 3:1），已在上表标注
- 全键盘可达：分区导航、卡片、灯箱关闭按钮；`:focus-visible` 统一 2px 主色描边
- 每张截图 `alt` 用 `state` 文案；装饰性元素 `aria-hidden="true"`
- 灯箱 `aria-label` / `aria-modal`，打开时焦点移入、Esc 关闭、关闭后回焦
- `prefers-reduced-motion` 关闭位移动画
- 语义标签：`header / main / section / figure / figcaption / footer / nav`

### 主题说明

站点其余页面均为浅色体系，本页**不单独引入深色模式**，避免跨页割裂；token 已集中定义，后续全站统一切换时可一处接入。

## 六、工程兼容约束（硬约束，重构不得破坏）

`scripts/capture-apk-page.py` 用正则定位并回写 HTML，以下锚点必须**逐字保留**：

1. `var DATA={...};` 后紧跟 `var cur=...`（`verify()` 依赖 `var DATA=(\{.*?\});\s*var cur=`）
2. 页面对象 `\{id:"...",name:"...",group:"..."` 与 `shots:[{file:"...",state:"...",version:"...",at:"...",fresh:1}]` 格式
3. `shotSets` 内 `fresh:{...}` / `legacy:{...}` 块及 `count:` 字段
4. `capturedAt:"..."` / `pageUpdatedAt:"..."`
5. `document.getElementById('stateNote').textContent='...';` 精确形式
6. `<div class="footer">...</div>` 唯一首个匹配
7. `id="verChip" / "capTime" / "pageTime" / "stateNote" / "app" / "filterbar" / "siteNav" / "lightbox" / "lightboxImg"`
8. `.shot` 元素上的 `data-project="ev-schedule-android" data-page="..." data-file="..."`（`review-widget.js` 挂载点）

同时保留：`/js/review-widget.js` + `mountAll`、`/js/site-nav.js` + `mountNav('siteNav','android-apk')`、`/js/track.js`、health 埋点、16 张图片路径与 `?v=20261112`、下载链接 `/apk-download.html`。

**结论**：`DATA` 对象字面量**一字不改**，只重写 CSS / 静态结构 / 渲染函数；因此补采脚本 `--status / --verify / --dry-run` 全部继续可用。
