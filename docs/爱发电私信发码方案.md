# 爱发电私信发码方案

## 一、核心逻辑变更

### 当前流程（有问题）

```
用户赞助 → 生成兑换码 + 立即生成激活码 → 私信发送激活码
                                              ↓
                                    激活码已绑定 afdian_user_id
                                    用户无法在真实手环上使用
```

### 新流程

```
用户赞助 → 生成永久兑换码（未使用） → 私信发送兑换码
                                            ↓
                              用户在手环App输入兑换码
                                            ↓
                              手环携带真实 deviceId 请求激活
                                            ↓
                              服务端生成激活码 → 返回给手环
```

### 关键区别

| | 旧方案 | 新方案 |
|:---|:---|:---|
| 私信发送内容 | 激活码 | **兑换码** |
| 兑换码有效期 | 跟随订单月数 | **永久（99个月）** |
| 兑换码状态 | `used: true`（立即标记已使用） | `used: false`（等用户激活） |
| 激活码生成时机 | 订单处理时立即生成 | 用户在手环上兑换时生成 |
| deviceId | `afdian_` + user_id（伪造） | 手环真实 deviceId |

## 三、数据存储变更

### 兑换码记录 `auth:redeem:{code}`

```json
{
  "code": "A3K9",
  "product_id": "01",
  "duration_months": 99,
  "used": false,
  "used_device_id": null,
  "generated_activation_code": null,
  "created_at": 1756128000000,
  "used_at": null,
  "source": "afdian",
  "user_name": "小明",
  "out_trade_no": "202106232138371083454010626"
}
```

**新增字段**：
- `user_name`：用户昵称，来自爱发电订单通知
- `out_trade_no`：订单编号，用于溯源

**变更字段**：
- `duration_months`：固定为 `99`（永久）
- `used`：初始为 `false`（等用户激活）
- `used_device_id`：初始为 `null`
- `generated_activation_code`：初始为 `null`

### 不再生成激活码

- 删除 `auth:activation:{activationCode}` 的创建
- 删除 `auth:activation_codes` 集合的添加
- 激活码在用户手环激活时由 `/api/activate` 生成

### 兑换码集合

新增：`auth:redeem_codes` 集合，记录所有兑换码

```
SADD auth:redeem_codes A3K9
```

## 四、代码改动清单

### `lib/afdian-processor.js`

1. **删除激活码生成逻辑**：移除 `generateActivationCode()` 调用
2. **删除激活记录保存**：移除 `auth:activation:{code}` 和 `auth:activation_codes`
3. **修改兑换码数据**：
   - `duration_months: 99`（永久）
   - `used: false`
   - 新增 `user_name`、`out_trade_no`
4. **修改私信内容**：发送兑换码，使用中文话术
5. **新增兑换码集合**：`SADD auth:redeem_codes`

### `admin_Dx23.html`（可选）

- 兑换码列表页增加"用户昵称"和"订单编号"列
