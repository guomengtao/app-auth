# Astrobox 插件开发与上架分析

> **背景**：EV课程表现已上架 Astrobox，用户搜索后下载推送到手环。  
> 本文分析 Astrobox 的插件/应用开发机制、复杂度，以及是否能通过插件管理课程表 App 数据。  
> **日期**：2026-09-19

---

## 一、什么是 Astrobox

Astrobox 是一款**免费开源**的第三方 Android 工具箱，专为小米/Redmi 穿戴设备（Vela/HyperOS 平台）设计。

| 属性 | 说明 |
|------|------|
| 平台 | Android（无 iOS 版） |
| 官网 | `https://astrobox.online/` |
| 定位 | 第三方表盘市场 + 快应用商店 + 固件刷写工具 |
| 开源状态 | 免费开源 |
| 核心功能 | 表盘浏览/安装、快应用搜索/下载/推送、固件管理、通知优化 |

### 1.1 与 EV课程表的关系

```
开发者（我们）
    │
    ├─ 开发 .rpk 快应用（Vela QuickApp 框架）
    ├─ 提交到米坛社区 bandbbs.cn（资源帖子）
    │       │
    │       └──► Astrobox 从社区索引抓取，展示给用户
    │
    ├─ 用户打开 Astrobox → 搜索「EV课程表」→ 下载 → 蓝牙推送到手环
    └─ 手环打开 App → 显示设备ID → 用户扫码激活 → 完成
```

**关键理解**：Astrobox **不是开发框架**，它是**分发渠道**。开发本身用的是 **Xiaomi Vela QuickApp 框架**。

## 二、Vela QuickApp 开发复杂度

### 2.1 项目结构（以 EV课程表为例）

从手环 App 的实际 `.ux` 源码可以看到典型结构：

```
EvTimetable/
├── manifest.json          # 应用配置（包名、版本、权限）
├── app.ux                 # 全局样式和配置
├── pages/
│   ├── index/
│   │   └── index.ux       # 主页（课程表视图）
│   ├── premium/
│   │   └── premium.ux     # 高级版/激活页（你前面看到的模板）
│   └── detail/
│       └── detail.ux
├── common/
│   ├── icons/             # 图标资源
│   └── ...
├── data/
│   ├── store.js           # 主题/状态管理
│   ├── auth-store.js      # 激活状态管理
│   └── version.js         # 版本号
├── lib/
│   └── crypto.js          # 加密工具
└── ...
```

### 2.2 技术栈

| 层面 | 技术 | 复杂度 |
|------|------|:------:|
| UI 模板 | `.ux` 文件（类 Vue 的单文件组件：`<template>` + `<script>` + `<style>`） | ⭐ 低 |
| 数据绑定 | `{{ }}` 插值，`if="{{}}"` / `for="{{}}"` 指令 | ⭐ 低 |
| JS 逻辑 | 标准 ES5 语法（无箭头函数、无 async/await） | ⭐⭐ 中 |
| 设备 API | `@system.router` / `@system.prompt` / `@system.vibrator` 等 | ⭐ 低 |
| 二维码 | `<qrcode>` 原生组件 | ⭐ 低 |
| 存储 | `@system.storage` / 自定义文件系统 | ⭐ 低 |
| 网络请求 | `@system.fetch` | ⭐ 低 |
| HTTP 通信 | GET/POST 到外部 API | ⭐ 低 |

### 2.3 开发环境

| 项目 | 详情 |
|------|------|
| IDE | **Xiaomi Aiot-IDE**（基于 VS Code），官方下载：`https://iot.mi.com/vela/quickapp/zh/content/guide/start/use-ide.html` |
| 操作系统 | **仅 Ubuntu**（Windows/macOS 需虚拟机或 WSL） |
| 语言 | JavaScript（ES5 兼容） |
| 调试 | 模拟器 / USB 连接手环调试 |
| 打包输出 | `.rpk` 文件 |

### 2.4 开发复杂度评估

| 维度 | 评估 | 说明 |
|------|:----:|------|
| 学习曲线 | ⭐⭐ 低-中 | 如果有前端经验（Vue/小程序），基本一天入门 |
| 基础设施 | ⭐⭐⭐ 中 | 需要 Ubuntu 环境（或用 WSL），IDE 安装有一定门槛 |
| API 限制 | ⭐⭐⭐⭐ 高 | ES5 语法、无现代 JS 特性、存储/网络 API 受限 |
| UI 开发 | ⭐⭐ 低 | 模板语法类似 Vue，组件式开发 |
| 调试 | ⭐⭐⭐ 中 | 需要真机调试，模拟器覆盖不全 |
| 设备兼容 | ⭐⭐⭐⭐ 高 | 不同型号（方屏 vs 胶囊屏 vs 圆屏）需分别适配 |
| **总体** | **⭐⭐⭐ 中等** | 能做，但比现代 Web 开发要受限不少 |

## 三、Astrobox 的「插件」概念澄清

### 3.1 Astrobox 没有传统意义上的「插件系统」

Astrobox 是一个**应用分发工具**，不是像 VS Code / Chrome / WordPress 那样的「宿主平台」。

在 Astrobox 生态中：
- 你开发的叫「**快应用**」（QuickApp，`.rpk` 文件）
- 用户在 Astrobox 里搜索/下载/推送 快应用到手环
- Astrobox **不提供**：运行时插件 API、进程间通信、数据共享接口

### 3.2 类比

| 概念 | Astrobox 生态 | 传统平台 |
|------|-------------|---------|
| 开发什么 | `.rpk` 快应用 | iOS App / Android APK |
| 分发渠道 | Astrobox（类似应用商店） | App Store / Google Play |
| 安装方式 | Astrobox 蓝牙推送到手环 | 下载安装到手机 |
| 运行环境 | 手环 Vela OS | iOS / Android |
| 是否有插件 API | ❌ 无 | ✅ 有 |

## 四、能否通过「插件」管理课程表 App 数据？

### 4.1 结论：不能（且没有必要）

Astrobox **没有开放插件接口**来让第三方读写其他快应用的数据。所以无法做一个「EV课程表管理插件」来管理用户数据。

### 4.2 但数据管理本来就不需要 Astrobox

EV课程表的数据管理**已经通过 Web 平台实现**，不需要在手环上做：

| 管理需求 | 当前实现 | 位置 |
|----------|---------|------|
| 订单查看 | `api/admin/health.js` → 订单列表 | Web 管理后台 |
| 激活记录 | `api/admin/health.js` → 激活记录 | Web 管理后台 |
| 激活码兑换 | `activate.html` | Web 页面 |
| 兑换码生成 | 爱发电购买 → 邮件私信 | 爱发电平台 |
| 消息推送 | `api/activate.js` → Redis PUBLISH → EvNotifier | Vercel + Redis |
| 走势图/统计 | EvNotifier 仪表盘 | Mac 桌面应用 |
| 用户安装指南 | `user-guide.html` | Web 页面 |

**数据流不经过手环 App**：手环 App 只负责显示设备 ID 和输入激活码，所有管理都在 Web 后端完成。

### 4.3 如果想增强手环 App 功能

只能通过**更新 `.rpk` 文件本身**来实现（修改 `.ux` 模板和 JS 逻辑），然后重新打包、重新提交到 Astrobox。用户需要重新下载推送。

## 五、Astrobox 上架流程与复杂度

### 5.1 当前 EV课程表的上架方式

EV课程表通过**米坛社区（bandbbs.cn）**上架：

```
1. 开发者提交 .rpk 文件到米坛社区资源帖
2. 填写资源信息（名称、描述、截图、适配型号）
3. Astrobox 从米坛社区索引抓取
4. 用户在 Astrobox 搜索 → 看到 EV课程表 → 下载
```

### 5.2 上架复杂度

| 步骤 | 复杂度 | 详情 |
|------|:------:|------|
| 打包 .rpk | ⭐⭐ 低 | IDE 一键导出 |
| 准备截图/描述 | ⭐ 极低 | 几张手环截图 + 文字说明 |
| 米坛社区发帖 | ⭐ 极低 | 注册账号 → 选择「资源」分类 → 上传附件 → 发布 |
| Astrobox 索引 | 自动化 | 无需额外操作，社区抓取是自动的 |
| 更新版本 | ⭐ 极低 | 编辑帖子 → 替换附件 → 保存 |

**总体**：上架流程非常简单，**不需要审核、不需要资质、不需要证书**。整个流程可以在 **10 分钟内完成**（不算调试时间）。

### 5.3 对比：官方快应用商店

如果选择上架**小米官方快应用商店**（不是 Astrobox），流程会复杂得多：

| 项目 | Astrobox（非官方） | 小米官方快应用商店 |
|------|:---:|:---:|
| 开发者资质 | 无需 | 企业营业执照 / 个人开发者认证 |
| 审核周期 | 无（即时发布） | 3~7 个工作日 |
| 软著/版权 | 无需 | 可能需要 |
| 签名证书 | IDE 自动生成 | 需要官方证书 |
| 用户覆盖 | 仅懂折腾的用户 | 所有小米手环用户 |
| 上架难度 | ⭐ 极低 | ⭐⭐⭐⭐ 高 |

### 5.4 适配多个机型

EV课程表目前适配了 5 个机型：

| 机型 | 屏幕形态 | bandbbs 链接 |
|------|---------|-------------|
| 10 Pro 方屏 | 矩形 | bandbbs.cn/resources/7778 |
| 9 Pro 方屏 | 矩形 | bandbbs.cn/resources/7828 |
| 9 Pro 胶囊 | 胶囊形 | bandbbs.cn/resources/7829 |
| S3/S4 圆屏 | 圆形 | bandbbs.cn/resources/7830 |
| 10 Pro 胶囊 | 胶囊形 | bandbbs.cn/resources/7877 |

**适配成本**：同一份代码，改 `<template>` 中的布局（不同屏幕形态的 CSS），每个机型约 **0.5~1 天**。

## 六、综合评估与建议

### 6.1 开发全套流程总览

```
阶段 1：开发（⭐⭐⭐ 中等，3~5 天）
  ├─ 安装 Ubuntu + Aiot-IDE
  ├─ 学习 .ux 模板语法（1 天）
  ├─ 编写 UI + 逻辑（2~3 天）
  ├─ 多机型适配（1~2 天）
  └─ 真机调试 + 修复

阶段 2：打包（⭐ 极低，10 分钟）
  └─ IDE 导出 .rpk → 得到 5 个 .rpk 文件

阶段 3：上架（⭐ 极低，10 分钟）
  ├─ 米坛社区发帖 × 5
  └─ 等待 Astrobox 自动索引（通常即时）

阶段 4：激活体系（我们的 Web 后端，已建设完成）
  └─ activate.html / Redis / 爱发电 对接
```

### 6.2 关键结论

| 问题 | 答案 |
|------|------|
| 开发复杂吗？ | ⭐⭐⭐ 中等。类似 Vue 小程序开发，但受 ES5 和手环 API 限制 |
| 上架复杂吗？ | ⭐ 极低。米坛发帖即可，无需审核，无需资质 |
| 能做插件管理数据吗？ | ❌ 不能。Astrobox 没有插件概念，它只是分发工具 |
| 需要插件管理吗？ | ❌ 不需要。所有数据管理已在 Web 后端实现 |
| 值得投入吗？ | ✅ 值得。用户入口在 Astrobox，保持 App 更新和上架是必须的 |

### 6.3 建议

1. **维持当前模式**：手环 App 做轻（只显示信息 + 输入激活码），重型管理放 Web
2. **缩减适配机型**：如果维护成本高，优先支持 10 Pro 方屏（占比最大）
3. **不需要开发 Astrobox 插件**：没有这个技术概念，且无实际需求
4. **考虑官方商店**：长期看，上架小米官方快应用商店能触及更多用户，但流程复杂需要企业资质
