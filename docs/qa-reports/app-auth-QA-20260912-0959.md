| `AFDIAN_PLAN_MAP` | ❓ 待确认 | ⏸ **仍无法静态确认** | `lib/afdian-processor.js:19` 读取；确认它需要鉴权接口 `?action=list`（返回 `plan_map`），无法匿名探测 |

**剩余风险（仍然可能是 P0，但范围收窄）**：若 `AFDIAN_PLAN_MAP` 未配或漏配某个 `plan_id`，买家付款后订单会被 `processOrder` 存为 `reason: "no_product_mapping"` 并 **skipped**，买家收不到兑换码、也没有任何提示（`lib/afdian-processor.js:76-87`）。

**给作者的一句话确认方式**：打开 `爱发电订单` 后台 tab，看 `plan_map` 是否非空、是否覆盖在售套餐的 `plan_id`。

### 3.2 P1-16 → 线上复现（首次实测，非静态推断）

**复现步骤（线上真实执行，2026-09-12 09:57，本机出口 IP）**

1. 模拟「用户打开激活页」：`POST /api/activate?section=visitor-track` × 2 → 均 200
2. 用户连续提交激活：`POST /api/activate` × 5

**实际结果**

| 第几次激活 | HTTP | 返回 |
|-----------|------|------|
| 1 | 400 | 兑换码必须是 4 位大写字母或数字 |
| 2 | 400 | 同上 |
| 3 | 400 | 同上 |
| **4** | **429** | **请求过于频繁，请稍后再试** |
| 5 | 429 | 同上 |

**期望**：限流 5 次/60s 应只作用于「激活」本身 → 用户应有 5 次试错机会。
**实际**：埋点吃掉 2 次 → **用户只有 3 次机会**。
**定位**：`activate.html:457`（页面加载即发 `visitor-track`）→ `api/activate.js:29`（埋点分支内也调 `checkIpRateLimit`）与 `api/activate.js:164`（激活分支）共用 `ratelimit:ip:<ip>`（`lib/rate-limit.js:43-44`，`IP_MAX_HITS=5` / 60s）。
**修复建议**（1 行）：埋点分支改用独立 key（如 `ratelimit:track:<ip>`）或直接不计数。

## 十一、已知风险·不急修（P4，仅记录，不排期、不催修）

以下均为**只可能造成资金损失**的白嫖/免单类，按约定只登记、不给方案：

1. **兑换码为 4 位 `[A-Z0-9]`（36^4 ≈ 168 万空间）**，理论可爆破；但 IP 限流 5 次/60s + 设备 50 次/天，实际爆破成本极高。损失上限 = 单份授权价。
2. **激活码为本地可逆编码**（`lib/crypto.js:200` `generateActivationCode`，`pad2(productId)+code+pad2(months)+device`），离线可推算——但需先拿到合法兑换码。
3. **拉单端点免鉴权**（见 P2-22）：可被反复触发消耗爱发电 API 配额，不直接造成资金损失。
