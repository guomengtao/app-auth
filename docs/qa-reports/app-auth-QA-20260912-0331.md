## 一、本轮结论摘要

> **一句话**：上轮 4 条 P0/P0-S 全部真修（线上实证），本轮**未发现新的 P0/P0-S**；唯一影响用户的是**「页面访问埋点和激活共抢同一个 IP 限流配额」——用户 1 分钟内输错 4 次兑换码就会被 429 拦下**，另需作者确认爱发电发码链路的两个环境变量。

**关键风险（只谈可用性）**
1. **P1-16**：`activate.html` 打开页面时的 `visitor-track` 埋点与「激活」请求共用 `ratelimit:ip:<ip>`（5 次/60 秒）。用户实际只有约 4 次试错机会，第 5 次起就是「请求过于频繁」。
2. **P0-22（待确认）**：爱发电支付后靠**私信 DM** 把兑换码发给买家，依赖 `AFDIAN_USER_ID/AFDIAN_TOKEN` + `AFDIAN_PLAN_MAP` 三个环境变量；任一个缺失 → **买家付款后收不到码，且无任何报错提示**。
3. **P2-21（潜伏）**：Postgres 代理模式的 `incr` 不过滤过期键，一旦主库从 Upstash 切到 Neon/Supabase，IP 限流键会**永久锁死**。当前生产是 Upstash 模式（线上实测 60 秒自动恢复），暂不触发。

**已确认修复（本轮线上实证）**：`?cron=1` 全量鉴权绕过、非 JSON 响应导致按钮卡死、**CRON_SECRET 未配导致 04:00/05:00 定时任务 401**（长期挂账项，本轮用线上返回码反证已配置）、switch-db 静默成功、兑换码解绑无按钮、run-task 401、设备限流阈值过严。

## 七、回归测试建议（给开发的可执行 checklist）

> 按用户操作路径组织，标 ⭐ 的是本轮必须验的。

**A. 用户激活主链路**
1. ⭐ 打开 `activate.html`，**连续 5 次输入错误兑换码**，第 6 次提交 → 记录是否在**第 5 次**（而非第 6 次）就出现 429（验证 P1-16）。
2. ⭐ 触发 429 后**只刷新页面再提交一次** → 观察是否仍 429（P1-16 加剧点）。
3. 等待 60 秒后重试 → 应恢复正常（线上已验证可恢复，防止 P2-21 回归）。
4. 用有效兑换码激活 → 页面应显示 18 位激活码 + 「复制激活码」按钮，点击能复制（含 `execCommand` 降级）。
5. 同一设备**再激活一次**同一个码 → 应幂等成功、时长不重复扣、激活码与上次相同。
6. 页面底部是否正确显示 `v1.5.51`（当前**预期是不显示**，见 P2-18；修好后应显示）。

**B. 换设备与解绑**
7. 换一个 deviceId 用同一个已用码激活 → 应 400「已被其他设备使用过」。
8. 后台「兑换码」页 → 点「解绑」→ 再用新设备激活 → 应成功。
9. 后台「激活记录」页 → 点 Unbind → 同上验证。

**C. 后台各栏目冒烟（11 个 tab 逐个点）**
10. dashboard / products / codes / records / decrypt / direct-activate / logs / quota / afdian-orders / visitors / settings —— 每个 tab 点开**不得空白、不得报错弹窗**。
11. 「产品」新增一个 → 「兑换码」按该产品生成 10 个 → 回到前台用其中一个激活 → 应成功。
12. 「兑换码」批量删除（purge unused）→ 刷新后数量应真的减少。
13. 「直开」选 1 个产品 + 设备 ID + 月份 → 提交 → 应返回激活码，且该激活码能在前台被 verify。

**D. 数据源与定时任务**
14. 设置 → 数据库状态 → 对 Neon/Supabase 点「切换」→ 应弹出校验弹窗；若数据不一致，**只能看到「先同步」按钮、看不到「切换」按钮**。
15. 定时任务页 → 对「数据库多路同步」点「立即执行」→ 应返回 success（验证 P0-14 不再回归）。
16. ⭐ 后台看 04:00 备份 / 05:00 同步的最新一次执行记录是否为 success（验证 P0-15 真正落地）。

**E. 爱发电（需作者配合）**
17. ⭐ 在 Vercel 环境变量确认 `AFDIAN_USER_ID`、`AFDIAN_TOKEN`、`AFDIAN_PLAN_MAP` 三个均有值。
18. ⭐ 用爱发电测试单（或查历史订单）确认买家**真的收到了含兑换码的私信**。
