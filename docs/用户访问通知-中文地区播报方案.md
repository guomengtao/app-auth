# 用户访问通知：中文地区播报方案

> 目标：所有推给 ev-notifier 的通知，**先说地区，再说用户做了什么**，全链路中文。
>
> 目标效果：
> - 弹窗/语音：`北京用户 访问 首页`
> - 弹窗/语音：`北京朝阳区用户 访问 激活页`
> - 弹窗/语音：`广东广州用户 点击购买 课程表`
> - 弹窗/语音：`山东淄博用户 激活成功 课程表`
>
> 「打通整个中文通知流程」= **地区文案规范（本方案 P0）** + **地区精度到区县（P1）** + **弹窗/语音/列表同一套模板（P0）**。

---

## 1. 现状盘点（已有能力）

| 环节 | 现状 | 位置 |
|---|---|---|
| 中文地区解析 | ✅ `resolveZhLocation({country,region,city})` → `省 市`，直辖市只出市名 | `lib/geo-zh.js` |
| 推送 payload | ✅ 三种通知都带 `location_zh`（`city_zh` 兼容） | `api/activate.js`、`api/admin/health.js`、`api/go.js` |
| 消费端取值 | ✅ `_zh_loc(p)`：`location_zh → city_zh → ''` | `ev_notifier.py` L737-739 |
| 访问语音 | ⚠️ 已是「地区在前」：`{地区}用户访问{页面名}` | `ev_notifier.py` L974-983 |
| 访问弹窗正文 | ⚠️ 地区**不在首行**（写成 `IP: 1.2.3.4 (广东 广州)`，无 IP 时才单列「归属地:」） | `ev_notifier.py` L812-840 |
| 购买/激活语音 | ❌ 不是「地区在前」：`收到购买点击，课程表，来自广州` / `新设备激活：…，来自广州` | `ev_notifier.py` L953-973、L926-950 |
| 地区精度 | ❌ 只到**市**，没有区县（"朝阳区" 拿不到） | Vercel 头部 / ip-api 都无区县级字段 |

**结论**：中文流程已通，但「说话顺序」不统一、弹窗里地区不醒目、**区县级精度缺失**。

## 2. 地区数据源分级（关键决策）

| 级别 | 数据源 | 精度 | 成本/时延 | 结论 |
|---|---|---|---|---|
| L1 | Vercel 头部 `x-vercel-ip-*` | 省 + 市 | 0 成本 0 时延 | 已有，主力 |
| L2 | `ip-api.com?lang=zh-CN`（`lib/ip-lookup.js`） | 省 + 市 | 免费 45 req/min，已缓存 24h | 已有，兜底 |
| L3 | **腾讯位置服务 IP 定位**<br>`apis.map.qq.com/ws/location/v1/ip?ip={ip}&key={KEY}` | 省 + 市 + **区县**（`result.ad_info.district`） | 需申请 key，有免费额度 | ✅ **推荐**（唯一能稳定给区县且合规的免费选项） |
| L3' | 纯真 IP 库 `qqwry.dat`（本地离线） | 省 + 市 + 区县（覆盖不全） | 离线、需定期更新库文件 | 备选（不想依赖外部 key 时） |
| ❌ | 高德 `restapi.amap.com/v3/ip`、百度 IP 定位 | 只到**市**，无区县 | — | **不满足需求，别走这条路** |
| ❌ | ip-api / ipinfo / ip.sb / ipwhois / ipapi.is | 只到市 | — | 同上 |

⚠️ **精度预期必须对齐**：IP 定位本质是「运营商出口 IP 归属地」，同一出口可能覆盖整城甚至多区，
所以区县**仅供参考**，命中就用、不命中就只播「省 市」，**不要向用户承诺区县一定准**。

## 3. 字段设计

```jsonc
{
  "country": "CN",
  "region": "Beijing",         // 英文原值，保留（回归/兼容）
  "city": "Beijing",
  "location_zh": "北京",        // 已有：省 市（直辖市只出市名）
  "district_zh": "朝阳区",      // 新增：区县，可空
  "location_full_zh": "北京朝阳区"  // 新增：展示/播报统一用它
}
```

拼接规则（写进 `lib/geo-zh.js`，只在一处实现）：

| 输入 | `location_zh` | `district_zh` | `location_full_zh` |
|---|---|---|---|
| 北京 + 朝阳区 | 北京 | 朝阳区 | **北京朝阳区**（省=市，去重） |
| 广东 + 广州 + 天河区 | 广东 广州 | 天河区 | **广东广州天河区** |
| 广东 + 广州（无区县） | 广东 广州 | — | **广东广州** |
| 山东（只有省） | 山东 | — | **山东** |
| 海外 Tokyo | 东京 | — | **东京** |
| 全空 | "" | — | **""** |

- 去重：`北京` + `北京朝阳区` 这种「市名重复」必须避免；直辖市判定用 `location_zh` 是否等于 `district` 所属市。
- 语音可读性：连续中文不加空格更适合 TTS（`北京朝阳区用户`），必要时用 `·` 或空格分隔省市（可配置）。

## 4. 通知文案规范（P0：先说地区）

统一模板：**`{地区}{主体} {动作} {对象}`**，无地区时降级去掉地区前缀。

### 语音（`enqueue_voice`）

| 类型 | 现状 | 改为 |
|---|---|---|
| `page_visit` | `{地区}用户访问{页面名}` ✅ | 保持，只把 `{地区}` 换成 `location_full_zh` |
| `purchase_click` | `收到购买点击，{产品}，来自{地区}` ❌ | `{地区}用户点击购买{产品}`（爱发电特例：`{地区}用户访问爱发电`） |
| `new_activation` | `新设备激活：{产品}，{时长}，用户{昵称}，设备{型号}，来自{地区}` ❌ | `{地区}用户激活{产品}，{时长}`（昵称/型号可选接在后面） |
| `activation_failure` | `激活失败：{原因}，来自{地区}` ❌ | `{地区}用户激活失败：{原因}` |
| `new_order` | `新订单，{用户}，{金额}` | `{地区}用户下单{产品}，{金额}`（订单目前无 geo，需 P1 补） |

- 无地区时：`用户访问首页` / `用户点击购买课程表`（**不要**出现 `未知用户`、不要把英文城市念出来）。
- 地区只在开头出现一次，句中不重复「来自 XX」。

### 弹窗正文（`notify_macos`）

**归属地提到第一行**，其余信息按重要性排序：

```
归属地: 北京朝阳区          ← 首行（有地区时）
页面: /activate.html
IP: 1.2.3.4
来源: https://...
14:32:05
```

- 现在写成 `IP: 1.2.3.4 (北京)`，地区藏在括号里，**不符合「先说地区」**。
- 无地区时不显示该行，不要显示 `CN`。

### 消息列表摘要（`_format_message_detail`）

`page_visit`：`/activate.html | 北京朝阳区`（地区已在，保持）
`purchase_click`：`课程表 | 广东广州`（已有）
`new_activation`：`课程表 3m | 归属地 北京`（建议补）

### 页面中文名（`_page_name_cn`）

已覆盖：首页 / 激活页面 / 下载页面 / `{slug}页面`。
建议补：`ev-timetable`→课程表页、`course-guide`→课程指南、`user-guide`→使用指南、`/go/*`→购买页。

## 6. 验证步骤

1. **映射单测**（P0 必过）：
   ```bash
   node -e "var g=require('./lib/geo-zh');
   [['Beijing','Beijing','Chaoyang'],['Guangdong','Guangzhou','Tianhe'],
    ['Shandong','Zibo',''],['','',''],[null,'Guangdong','Shenzhen']]
   .forEach(function(c){console.log(g.resolveZhLocationFull({region:c[0],city:c[1],district:c[2]}))})"
   ```
   期望：`北京朝阳区` / `广东广州天河区` / `山东淄博` / `` / `广东深圳`。
2. **链路验证**：`curl -X POST ".../api/admin/health?section=visit"` → 看 Upstash stream 里那条 payload 是否含 `location_full_zh`。
3. **真机验证**：重启 Ev Notifier → 人为访问一次激活页 → 听语音是否为「北京朝阳区用户访问激活页面」，看弹窗首行是否为「归属地: …」。
4. **降级验证**：把 `location_full_zh` 置空发一条测试消息（`{action:"test_curl"}` 或手工 XADD），确认语音是「用户访问首页」而不是「未知用户 访问 首页」、不会念英文。

## 8. 风险与注意事项

| 风险 | 应对 |
|---|---|
| 区县不准（运营商出口 IP 覆盖多区） | 只在 L3 命中时展示；文案不承诺「精确位置」 |
| L3 外部依赖超时/限额 | 超时 ≤800ms + 失败静默回落；key 未配置直接跳过 |
| 直辖市重复（"北京 北京朝阳区"） | 拼接逻辑集中在 `lib/geo-zh.js` 一处去重，禁止各业务文件自己拼 |
| 语音太啰嗦（小屏/长文案） | 模板固定为「地区+用户+动作+对象」，昵称/型号等次要信息只进弹窗不进语音 |
| 中文与数字/英文混读难听 | 产品名保持原名（如 `EV课程表`），地区走纯中文 |
| 改了模板但老消息格式不一 | 新模板只作用于新消息；老消息靠 `_zh_loc` 回落，不做历史重放 |
