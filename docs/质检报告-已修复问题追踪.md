## 已修复问题详情

### P0-1 ✅ 已修复（自动）激活记录表格永远空白

**根因**：`ADMIN_MODE = 'local-first'` 默认值导致 `renderRecordsTable` 返回值在 local-first 分支被丢弃。

**修复方式**：提交 `62b3cb1` 删除整个 local-first 模式。

### P0-2 ✅ 已修复（自动）7 类写操作被拦截

**根因**：`requireOnlineMode()` 拦截 local-first 模式下所有增删改。

**修复方式**：提交 `62b3cb1` 删除 `requireOnlineMode()` 函数及所有调用点。

### P0-3 / P0-9 ✅ 已修复（手动）兑换码删除功能

**根因**：后端没有 DELETE 分支（P0-3），且前端调路径段路由 `/redeem-codes/XXX` 与后端根路由 `/redeem-codes?code=` 不匹配（P0-9）。

**修复步骤**：

1. **提交 `e2f64fa`**：给 `redeem-codes.js` 加 DELETE 分支（支持 query param 和 body），新建 `purge.js` 批量删除
2. **提交 `f81485f`**：改前端路径段路由 → query param（一行改动）

**当前状态**：
- ✅ 单条删除：`DELETE /api/admin/redeem-codes?code=ABC123`
- ✅ 批量 purge：`POST /api/admin/redeem-codes/purge?scope=used|unused&product_id=xxx`

### P0-4 ✅ 已修复（手动）激活写入非原子

**根因**：`api/activate.js` 主链路用 `Promise.all` 并发发 5 条独立命令，任一失败抛异常，其他已发送命令可能成功。

**修复方式**：提交 `e2f64fa` 改用 `redis.pipeline()`（两处：主激活 + reuse 重激活）。

```js
// 修复前：5 个独立并发 Promise.all
// 修复后：pipeline 顺序执行，单条失败不抛，exec 后统一检查 results
var writePipeline = redis.pipeline();
writePipeline.set(...); writePipeline.sadd(...); writePipeline.incr(...);
var writeResults = await writePipeline.exec();
var writeFailed = writeResults.some(function (r) { return r === null; });
```

### P0-5 ✅ 已修复（手动）Webhook 无签名放行

**修复方式**：提交 `e2f64fa`

| 场景 | 修复前 | 修复后 |
|---|---|---|
| 无 sign | 跳过校验 → 发货 | **400 sign_required** |
| 签名错误 | 200 { ec: 200 } | **400 sign_verify_failed** |
| 处理器异常 | 200 { ec: 200 } | **500 internal_error**（触发平台重试） |

### P0-7 ✅ 已修复（外部）通知器 RESP 解析器丢消息

**修复提交**：`44e1fa9`（本轮之前已有修复，非本次会话所做）

**修复内容**：

- `ev_notifier.py:393` 已改为 `for reply in proto.parse_all()`
- 解决了「TCP 拆包」「多条合并到达」两个丢消息场景
