# EvNotifier 运维手册 —— 换机器 / 重装 / 排障

> 目的：避免「换了台 Mac（或重装系统）之后通知收不到、补拉失效、面板打不开」时
> 不知道从哪下手。**本文只讲怎么把机制跑起来和怎么修，原理见
> `离线补拉与已读系统设计.md`。**
>
> 一句话记住：**客户端靠两样东西活着 —— ① LaunchAgent 常驻进程 ② 一组环境变量。
> 这两样都不在仓库里，换机器必漏。**

---

## 1. 这套东西由哪几块组成

| 组件 | 位置 | 作用 | 换机器要处理 |
|---|---|---|---|
| 客户端脚本 | `tools/ev-notifier/ev_notifier.py` | 收通知、弹窗、语音、面板 | clone 仓库即可 |
| 常驻进程 | LaunchAgent `~/Library/LaunchAgents/com.evnotifier.agent.plist` | 开机自启 + `KeepAlive` 崩溃拉起 | **由脚本自动生成**，别手工拷贝 |
| 环境变量 | `~/Documents/guomengtao/app-auth/.env`（+ 可选 `~/.ev-notifier.env`） | Upstash 凭据、共享密钥 | **必手工重建** |
| 本地状态 | `~/.ev_sync_state.json` 等（见 §9） | 水位线、消息库、偏好 | 可选迁移 |
| 服务端接口 | `https://app-auth.gudq.com/api/admin/health?section=delivery-*` | 补拉 / 回执 / 查询 | 无需处理 |
| 测试 | `./tools/ev-notifier/tests/run_tests.sh`、`smoke_online.py` | 改完/换完自检 | 跑一遍即可 |

## 2. 依赖清单（换机器必装）

```bash
# 1) Python（LaunchAgent 里写的就是这个绝对路径）
brew install python@3.14

# 2) 依赖：rumps(UI) + redis(实时订阅) + pyobjc 的 WebKit(面板渲染)
/opt/homebrew/opt/python@3.14/bin/python3.14 -m pip install \
    "rumps>=0.4.0" redis pyobjc-framework-WebKit
```

⚠️ `requirements.txt` 里**只有 `rumps`**，漏了 `redis` 和 `pyobjc-framework-WebKit`。别只 `pip install -r requirements.txt`。

自查是否装全（前 6 个全 OK 才算好，`webview` 只是可选兜底）：

```bash
/opt/homebrew/opt/python@3.14/bin/python3.14 -c "
import importlib
for m in ('rumps','redis','objc','AppKit','Foundation','WebKit','webview'):
    try: importlib.import_module(m); print(' OK  ', m)
    except Exception: print(' MISS', m)
"
```

| 缺哪个 | 后果 |
|---|---|
| `rumps` | 进程直接起不来（ImportError） |
| `redis` | 界面在，但永远连不上、收不到任何实时通知（`redis_loop` 反复报错） |
| `WebKit` | 状态栏和通知正常，但面板改用兜底渲染（纯文本 / 外部浏览器），体感"面板变丑/打不开" |
| `objc` / `AppKit` / `Foundation` | 随 `rumps` 一起装（pyobjc-framework-Cocoa），缺了跟缺 `rumps` 一样 |
| `webview`（可选） | 只在没有 WebKit 时当兜底，没有也无所谓 |

## 3. `.env` 需要哪些 key

路径：`~/Documents/guomengtao/app-auth/.env`（`.env*` 已被 `.gitignore` 忽略，**不会进仓库**）

```ini
KV_REST_API_URL=https://xxxx.upstash.io      # Upstash 控制台 → REST API
KV_REST_API_TOKEN=xxxx                        # 同上
EV_SYNC_TOKEN=<48 位十六进制随机串>            # 自定义；必须与 Vercel 上的同值
```

生成一个新 token：

```bash
python3 -c "import secrets; print(secrets.token_hex(24))"
```

### ⚠️ 最容易卡住的地方：`EV_SYNC_TOKEN` 拉不回来

它在 Vercel 上是 **Secret** 类型，CLI 明确提示 *"hidden in the dashboard and unavailable to pulls"* ——
**`vercel env pull` 拿不到值**（只能得到占位符，代码里对 `[SENSITIVE]` 有专门跳过逻辑）。

所以换机器时你**必须事先有记录**。建议二选一：

- 存进密码管理器（推荐，一条记录写清「Vercel Production / 本机 .env 两处都要一致」）；
- 或者干脆**轮换**（重新生成一个，服务端和客户端一起换，见 §8）。

### 环境变量文件的读取顺序（后者覆盖前者）

`ev_notifier.py` 按这个顺序读，**后面的会覆盖前面的同名 key**：

```
1. ~/Documents/guomengtao/app-auth/.env
2. ~/Documents/guomengtao/app-auth/.env.local
3. ~/.ev-notifier.env
```

> 建议：`EV_SYNC_TOKEN` **只写一处**（就写 `.env`）。两处都写且值不同时，
> 会出现「本机以为配好了、服务端却认为不匹配」的幽灵问题。

## 4. 换机器完整步骤（可照抄）

```bash
# ── 1. 拉代码 ──────────────────────────────────────────
cd ~/Documents/guomengtao
git clone git@github.com:guomengtao/app-auth.git
cd app-auth

# ── 2. 装依赖（见 §2）──────────────────────────────────
brew install python@3.14
/opt/homebrew/opt/python@3.14/bin/python3.14 -m pip install "rumps>=0.4.0" redis pyobjc-framework-WebKit

# ── 3. 建 .env（见 §3，三个 key）───────────────────────
#    注意：上游 token 拿不回来 → 用你事先记下的值，或走 §8 轮换

# ── 4. 可选：迁移本地状态（见 §9，想保留历史消息/client_id 就做）
#    cp /path/to/old/home/.ev_messages.json ~/
#    cp /path/to/old/home/.ev_sync_state.json ~/

# ── 5. 跑一次（会自动重写 LaunchAgent，写入正确的 python 绝对路径）
/opt/homebrew/opt/python@3.14/bin/python3.14 tools/ev-notifier/ev_notifier.py &
sleep 5

# ── 6. 验证 ────────────────────────────────────────────
launchctl list | grep evnotifier          # 应看到 com.evnotifier.agent
tail -5 ~/.ev_debug.log                   # 应看到 sync[reconnect] ...
python3 tools/ev-notifier/tests/smoke_online.py   # 应全 PASS（自动从 .env 读 token）
```

**第 5 步是关键**：`ensure_auto_start()` 会用**当前 python 的绝对路径**重写 plist 并 `launchctl bootstrap`。
所以换机器后只要用新机器的 python 跑一次脚本，LaunchAgent 就自动修好了 —— **不要从旧机器拷贝 plist**。

## 5. 换机器后的预期行为（别误判成故障）

| 现象 | 是否正常 | 说明 |
|---|---|---|
| 看不到换机器之前的历史消息 | ✅ 正常 | 新 `~/.ev_sync_state.json` → `last_seq=0` → 首次同步走 **bootstrap 直接跳到当前最大 seq，不重放历史**（这是有意设计，否则会把几个月的访问通知全灌进来）。**要历史就把旧机器的 `~/.ev_messages.json` 拷过来。** |
| 面板「恢复次数」是 0 | ✅ 正常 | 本轮进程还没补拉过 |
| 崩溃计数从 0 开始 | ✅ 正常 | 记在 `~/.ev_notifier_state.json`，没迁移就重头数 |
| `~/.ev_last_id_v1.x.x` 一堆小文件 | ✅ 正常 | 历史遗留（旧版 stream 偏移量），当前 PUB/SUB + 游标方案已不用 |

## 6. 故障速查表（症状 → 原因 → 处理）

| 症状 | 最可能原因 | 怎么确认 / 处理 |
|---|---|---|
| **状态栏图标根本不出现** | 进程起不来：`.env` 缺失 → `load_env()` 里 `sys.exit(1)` | `cat ~/.ev_notifier_stderr.log`，会看到 `ERROR: Config not found.` → 补 §3 的 key |
| **每次启动立刻退出，日志写 `Another instance is already running (PID xxxx)`** | **陈旧 PID 文件** `~/.ev_notifier.pid`，且里面的 PID 在新机器上恰好被别的进程占用 → `os.kill(pid,0)` 成功 → 误判"已在运行" | `rm ~/.ev_notifier.pid` 后重启。**换机器千万不要拷这个文件** |
| 图标在、`Online`，但**离线期间的消息补不回来** | `EV_SYNC_TOKEN` 没配 / 两处不一致 → 401 | `grep sync ~/.ev_debug.log`，看到 `delivery-sync unavailable -> fallback legacy undelivered` 就是它 → 核对 §3 |
| 图标在但一直 `Reconnecting`，**任何通知都没有** | Upstash 凭据错 / `redis` 未安装 | `cat ~/.ev_notifier_stdout.log`；重装 `redis` |
| **开机不自启** | LaunchAgent 里的 python 路径失效（brew 升级改名，如 `python@3.14`→`python@3.15`） | `launchctl list \| grep evnotifier` 为空 → 用新 python 跑一次脚本自动重写 plist（§4 第 5 步）。**不要拷旧 plist** |
| 面板**空白/打不开** | 渲染异常 | `grep _refresh_content ~/.ev_debug.log`。新版本会渲染出红色错误页而不是纯空白 |
| 面板消息列表只有 80 条 | ✅ 不是故障 | 存储是全量保留的，但**渲染上限 80 条**（HTML 太大会让 WebKit 加载失败）。面板上会写「共 N 条，显示最新 80 条」 |
| 通知重复弹两次 | 补拉与实时同时命中 | 幂等入口会拦掉绝大多数；若真出现，把 `~/.ev_debug.log` 里两条 `handle_message` 记录发出来 |
| 状态栏角标数字和列表对不上 | 已读口径 | 角标 = 本地 `read=false` 条数，打开面板停留 1.2 秒会把可见的自动标已读 |

## 8. 密钥轮换 / 换机器时 token 找不回来

`EV_SYNC_TOKEN` 的值既然拉不回来，最干净的做法就是**两边一起换新的**：

```bash
cd ~/Documents/guomengtao/app-auth

# 1) 生成新值
NEW=$(python3 -c "import secrets; print(secrets.token_hex(24))")

# 2) 本机 .env 换掉旧值（保持只出现一处）
python3 - "$NEW" <<'PY'
import re, sys, pathlib
new = sys.argv[1]
p = pathlib.Path(".env")
lines = p.read_text(encoding="utf-8").splitlines(keepends=True)
out, done = [], False
for ln in lines:
    if ln.startswith("EV_SYNC_TOKEN="):
        out.append("EV_SYNC_TOKEN=%s\n" % new); done = True
    else:
        out.append(ln)
if not done:
    out.append("\nEV_SYNC_TOKEN=%s\n" % new)
p.write_text("".join(out), encoding="utf-8")
print("本机 .env 已更新")
PY

# 3) 重启客户端（先做本机，避免窗口期）
launchctl kickstart -k "gui/$(id -u)/com.evnotifier.agent"

# 4) 再换 Vercel（Secret 不能直接改值，先删再建）
vercel env rm EV_SYNC_TOKEN production --yes
printf '%s' "$NEW" | vercel env add EV_SYNC_TOKEN production
git commit --allow-empty -m "chore: rotate EV_SYNC_TOKEN" && git push   # 触发重新部署

# 5) 验证：405/401/200 三个分支
sleep 90 && python3 tools/ev-notifier/tests/smoke_online.py
```

> ⚠️ **顺序不能反**：先本机 + 重启客户端，**再**改 Vercel。
> 反了的话，部署完成到客户端重启之间补拉会一直 401（实时 PUB/SUB 不受影响）。
>
> ⚠️ 改完记得**把新值存进密码管理器**，否则下次换机器又回到 §3 的坑。

## 9. 本地状态文件清单（`~` 下，换机器时可选迁移）

| 文件 | 用途 | 要不要迁移 |
|---|---|---|
| `.ev_sync_state.json` | `client_id` + `last_seq` 水位线 | **建议迁移**（否则 client_id 变、历史不重放） |
| `.ev_messages.json` | 消息库（**全量保留，不截断**；会随时间持续增长） | 想保留历史就迁移 |
| `.ev_notify_settings.json` | 弹窗/语音/访客语音开关 | 建议迁移（省得重设） |
| `.ev_visitors.json` | 访客记录（上限 2000） | 随意 |
| `.ev_received.json` / `.ev_poll_log.json` | 旧版统计/轮询日志 | 不用 |
| `.ev_debug.log` | 调试日志（客户端最重要的排障入口） | 不用（新的更干净） |
| `.ev_notifier_state.json` | 崩溃计数 | 不用 |
| **`.ev_notifier.pid`** | 单实例锁 | **绝对不要迁移**（见 §6 第 2 行） |
| `.ev_notifier_stdout.log` / `.ev_notifier_stderr.log` | print / 崩溃输出 | 不用 |
| `.ev_last_id_v1.x.x` | 历史遗留 | 不用 |

## 10. 三条铁律

1. **仓库是 public** —— 任何密钥都只能放 `.env`（已 gitignore）或 Vercel 环境变量，**绝不能写进代码、文档、commit message**。
2. **改完必须跑测试**：`./tools/ev-notifier/tests/run_tests.sh`（离线，147 项）。这个应用是「Python 字符串里塞 HTML/JS」，`py_compile` 证明不了面板能渲染。
3. **部署 = `git push origin main`**，Vercel 自动构建（约 60–90 秒）。客户端改动则要**重启客户端**才生效（`launchctl kickstart -k`）。
