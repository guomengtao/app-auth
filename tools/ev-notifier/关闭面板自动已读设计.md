# EvNotifier：关闭面板 → 自动全部已读

> **一句话需求**：用户点红叉关掉面板 = 「这些消息我都不看了」。关窗瞬间把本地所有消息标为已读（含补发 `read` 回执），下次打开面板未读数归零、导航角标消失。
>
> 代码基线：`tools/ev-notifier/ev_notifier.py`（ev-notifier v2.3.x 单文件）。本文只描述「关窗即已读」，不改动补拉/推送链路。

---

## 0. 结论速览

| 事项 | 结论 |
|---|---|
| 数据层能力 | **已具备**，直接复用 `mark_all_messages_read()`，无需新逻辑 |
| 唯一障碍 | `windowWillClose_`（`:5208`）**实测从未被调用**，不能作为触发点 |
| 推荐做法 | ① 真 `NSWindowDelegate`（`NSObject` 子类）拿关闭事件 + ② 主线程可见性轮询兜底 |
| 幂等 | `mark_all_messages_read()` 天然幂等（dirty 才落盘、只发增量回执），双触发无副作用 |
| 关窗后新到的消息 | **保持未读**（这是需求语义，不能被"顺手"标掉） |
| 风险 | 关窗路径严禁碰窗口对象/刷新 WebView（否则复现 SIGTRAP，见 `打开面板崩溃与自动重启统计.md`） |

## 1. 需求（做什么）

| 项 | 定义 |
|---|---|
| 触发 | 面板窗口被关闭：红叉 / `Cmd+W` / 程序化 `close()` |
| 动作 | 调 `mark_all_messages_read()`；返回变更数 `n > 0` 时补发 `read` 回执 |
| 结果 | `count_unread() == 0`；菜单栏标题「未读: 0」；导航角标消失；统计卡「未读消息」归零；消息列表仍有数据（默认筛选 `all`） |
| 非目标 | 不删消息、不改保留策略、不改服务端投递状态机（只是多发一次 `read` 回执）、不触发补拉 |

### 1.1 与既有"已读"的关系

- **可见即已读**（`reportVisibleRead()` `:3460`）只标"渲染出来且未被筛选隐藏"的卡片，且要求 `document.hasFocus()`。它是本需求的**子集**：关窗时列表里没滚到的部分，靠本需求补齐。
- **手动 Mark All Read**（面板按钮 → `ev://mark-read=all` → `_mark_all_read()` `:4936`）与本需求**动作完全一致**，差别只是触发源，且 `_mark_all_read()` 会额外切页 + 刷新（关窗场景不适用，见 §4）。

## 2. 现状：可直接复用的东西

| 能力 | 位置 | 说明 |
|---|---|---|
| `mark_all_messages_read()` | `:461` | 遍历内存消息库，`read=False → True` 并写 `read_at`；`changed` 才 `_mark_messages_dirty()`（后台 2s 合并落盘）；顺带 `_enqueue_receipt(mid, "read")` |
| `_enqueue_read_receipts_for_all()` | `:483` | 逃生舱：给**所有**带 `messageId` 的消息补一次 `read` 回执（覆盖历史遗留） |
| `_flush_receipts()` | `:781` | 按事件归并、每 100 条一批 POST `/api/admin/health?section=delivery-callback`；内部 try/except |
| `mark_read(keys)` | `:428` | 按 `_msg_key()` 精确批量标记（`s:seq` → `m:messageId` → `t:time|type`） |
| `count_unread()` | `:419` | 唯一未读口径（`_unread_cache`，标记路径已负责失效） |
| 菜单栏未读数 | `:3298-3300` | `_build_status_summary()` → `未读: N` |
| `ev://` 动作通道 | `:3023` | `mark-read=` / `read-one=` / `read-visible=` 三个 action 已存在 |

> 结论：**本需求的价值 100% 在"触发时机"上**，数据层零改动。

## 3. 关键技术障碍

`_create_window()`（`:3264-3266`）确实注册了 `NSWindowWillCloseNotification` observer：

```3264:3266:tools/ev-notifier/ev_notifier.py
        nc = NSNotificationCenter.defaultCenter()
        nc.addObserver_selector_name_object_(
            self, 'windowWillClose:', NSWindowWillCloseNotification, self._window)
```

但 `windowWillClose_`（`:5208`）里自己写着实测结论：

> ⚠️ 用**纯 Python 对象**注册的 selector 在应用里**从未被调用**（`_retired` 恒为 0）。

**踩坑姿势**：直接把 `mark_all_messages_read()` 塞进 `windowWillClose_` → 功能**静默不生效**（不报错、无日志），且因为该方法从不执行，`self._window` 也**永远不会被清空**（关窗后它只是 `isVisible() == False`）。

### 3.1 方案对比

| 方案 | 实现 | 可靠性 | 代价 / 风险 |
|---|---|---|---|
| **A. 真 delegate** | 新增 `WindowDelegate(NSObject)` 实现 `windowWillClose_`，`window.setDelegate_()`，并持有引用 | 高（事件精确、即时） | 需新类；`_teardown_window()`（`:3224`）要 `setDelegate_(None)` 防悬挂；pyobjc 里 selector 名必须是 `windowWillClose_` |
| **B. JS 卸载钩子** | 面板 JS `window.onpagehide` / `onbeforeunload` 里 `location='ev://mark-read=all'` | **低** | WebView 卸载时导航请求常被丢弃；且 `_teardown_window()` 已 `setPolicyDelegate_(None)`，旧页面回调不再进来 |
| **C. 可见性轮询（兜底）** | 主线程 `AppHelper.callLater` 每 1s 查 `isVisible()`，`True→False` 边沿触发 | 高 | ≤1s 延迟；`_window is None` 时要跳过（防访问悬垂对象）；最小化也变"不可见"，需用 `isMiniaturized()` 区分 |
| **D. 下次打开时补偿** | `_show_impl()`（`:3139`）里先把上次遗留未读全标已读 | 中 | **语义错**（"打开才已读" ≠ "关闭即已读"），用户看不到即时归零，弃用 |

**采用 A + C 双保险**：A 负责精确与即时，C 负责"delegate 失效 / 窗口被系统关闭 / 异常路径"时不漏。两者共用一个 `_on_window_closed()`，内部加一次性门闩保证幂等。

## 4. 语义细节与边界（必须遵守）

1. **只清"关窗这一刻已存在的消息"**。关窗后新到的消息应继续走未读 + 弹窗提醒。
   - 方案 A 的触发是同线程事件，误标窗口 ≈ 0，直接用 `mark_all_messages_read()`。
   - 方案 C 有 ≤1s 延迟 → 稳妥做法：触发时先用 `mark_read(_msg_key(m) for m in load_messages())` 的**关窗瞬间快照**，而不是 `mark_all`。
   - 注意：消息条目**没有数值时间戳字段**（只有 `time` 字符串 `%Y-%m-%d %H:%M:%S` 和可选 `seq`），要"按时间卡"只能用快照或字符串比较，别去找 `ts`。
2. **不要调 `_mark_all_read()`**。它内部会 `_current_page = "messages"` + `_refresh_content()`，而 `_refresh_content()` 会往**已关闭的 WebView** 灌 data URL —— 正是历史 SIGTRAP 的成因类型。关窗路径只调数据层。
3. **不阻塞主线程**。标记是内存循环（万级消息 < 10ms，可接受）；回执发送必须放 daemon 线程（`threading.Thread(target=_flush_receipts, daemon=True).start()`），与 `_mark_all_read()` 保持一致。
4. **幂等**。A 与 C 可能先后触发，用 `self._close_mark_done` 门闩（或在下次 `show()` 时重置）；底层 `mark_all_messages_read()` 本身也幂等：无 `False→True` 就不落盘、不发回执，重复触发零副作用。
5. **空库 / 全已读**：返回 0 → 不落盘、不发回执、**不写 debug log 噪音**（或只写一行 debug）。
6. **面板从未获得焦点就关掉**：**仍然标记**。用户主动关闭窗口是明确交互；与"可见即已读要求焦点"不冲突（后者是自动行为，前者是显式动作）。
7. **最小化不算关闭**（建议）：`isMiniaturized()` 为真时不算"关窗"，避免用户只是收起来就被清未读。
8. **退出应用（Cmd+Q）不算关闭**（建议）：走 `NSApplicationWillTerminate` 标记会误标"退出前最后一秒到的消息"，收益低；只做窗口级关闭。
9. **delegate 生命周期**：`_create_window()` 里创建并**保留强引用**（`self._window_delegate`）；`_teardown_window()`（`:3224`）与 `windowWillClose_` 清理路径里 `window.setDelegate_(None)`，否则 delegate 被提前释放 → 调用已释放对象 → 又一类崩溃。
10. **不动 `_retired` 语义**：现有"先建新、再拆旧、旧三件套留在 `_retired`"的纪律（`:3208-3246`）必须保留，delegate 也要一起进 `_retired`。

## 6. 验收标准

1. 面板有 N 条未读 → 关窗 → `~/.ev_messages.json` 中这些消息 `read=true`、`read_at` 有值；`count_unread() == 0`。
2. 菜单栏标题变为 `未读: 0`（`:3300`）。
3. 再次打开面板：消息导航项**无角标**、统计卡「未读消息」= 0、列表**非空**（默认筛选 `all`）。
4. **关窗后新到的消息仍是未读**（可弹窗、可再次点亮角标）。
5. 关窗不增加崩溃计数（`~/.ev_notifier_state.json` 的 `abnormal_exit_count` 不变），`~/.ev_debug.log` 无 ERROR，且出现类似 `mark_all_read_on_close: marked N as read`。
6. 反复开/关 5 次，`~/.ev_debug.log` 无异常，`_retired` 长度不超过 3（`:3245`）。

## 7. 待确认的产品问题

1. **最小化（黄点）算不算关闭？** 建议不算。
2. **要不要设置开关？** 建议进设置页 `settings` 组，默认开启；关闭后回退到"仅可见即已读"。
3. **要不要补发 `read` 回执到服务端？** 建议补（与手动 Mark All Read 口径一致，服务端投递统计才不会长期挂着未读）。
