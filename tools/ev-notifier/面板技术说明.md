## 技术架构

```
┌─────────────────────────────────────────────────┐
│              Ev Notifier 菜单栏应用               │
│  (rumps - 纯 Python 菜单栏程序)                   │
│                                                   │
│  ┌───────────────────────────────────────────┐   │
│  │  点击"打开面板"                            │   │
│  │     ↓                                     │   │
│  │  1. Python 生成完整 HTML 仪表盘            │   │
│  │     (包含 CSS + 数据 + 交互逻辑)           │   │
│  │     ↓                                     │   │
│  │  2. 写入 ~/.ev_dashboard.html              │   │
│  │     ↓                                     │   │
│  │  3. 启动子进程: pywebview 桌面窗口         │   │
│  │     (独立 Python 进程, 主线程运行)          │   │
│  └───────────────────────────────────────────┘   │
└─────────────────────────────────────────────────┘
                      ↓
┌─────────────────────────────────────────────────┐
│         pywebview 子进程 (桌面窗口)               │
│                                                   │
│  ┌───────────────────────────────────────────┐   │
│  │  macOS 原生窗口 (NSWindow)                  │   │
│  │     ↓                                     │   │
│  │  WKWebView (系统内置浏览器引擎)             │   │
│  │     ↓                                     │   │
│  │  渲染 HTML 仪表盘                           │   │
│  └───────────────────────────────────────────┘   │
└─────────────────────────────────────────────────┘
```

---

## 为什么是"网页壳子"？

### 这是行业标准做法

| 知名应用 | 技术方案 | 说明 |
|---------|---------|------|
| **VS Code** | Electron (Chromium) | 整个编辑器就是网页 |
| **Slack** | Electron (Chromium) | 同上 |
| **Discord** | Electron (Chromium) | 同上 |
| **Notion** | Electron (Chromium) | 同上 |
| **Figma** | 自研 + WebView | 部分使用网页渲染 |
| **微信桌面版** | WebView 嵌入 | 聊天窗口用网页渲染 |
| **钉钉桌面版** | Electron | 同上 |

**结论：现代桌面应用 80% 以上都是"网页壳子"。**

---

## 我们的方案 vs Electron

| 对比项 | 我们的方案 (pywebview) | Electron |
|-------|----------------------|----------|
| 体积 | ~50MB (Python + 依赖) | ~150MB+ (Chromium 内置) |
| 内存占用 | ~100MB | ~300MB+ |
| 启动速度 | 快 (系统 WKWebView) | 慢 (自带 Chromium) |
| 渲染引擎 | macOS 系统 WKWebView | 内置 Chromium |
| 打包大小 | 小 | 大 |
| 跨平台 | ✅ macOS/Windows/Linux | ✅ 同上 |

## 为什么不用纯原生 UI？

### 尝试过的失败方案

1. **AppKit WKWebView (内嵌)** → Python 3.14 下 segfault 崩溃
2. **AppKit NSTextView (纯文本)** → 无法渲染 CSS 样式，只能显示纯文本
3. **浏览器打开** → 用户体验差，不是桌面应用

### 纯原生 UI 的问题

```python
# 如果用纯 AppKit 写仪表盘，需要：
- 手写每个控件 (按钮、表格、图表)
- 手写布局系统 (Auto Layout)
- 手写主题切换 (深色/浅色模式)
- 手写响应式适配
- 代码量: 5000+ 行

# 用 HTML/CSS 写仪表盘：
- CSS 直接写样式
- 浏览器引擎自动处理布局
- 主题切换改 CSS 变量即可
- 响应式用 CSS media query
- 代码量: 1500 行
```

## 数据流说明

```
Redis/Upstash (数据源)
       ↓
  Python 拉取数据
       ↓
  生成 HTML 字符串 (包含 CSS + JS + 数据)
       ↓
  写入 ~/.ev_dashboard.html
       ↓
  pywebview 子进程读取 HTML
       ↓
  macOS WKWebView 渲染
       ↓
  用户看到仪表盘
```

## 文件说明

| 文件 | 作用 |
|------|------|
| `ev_notifier.py` | 主程序，菜单栏 + 数据拉取 + HTML 生成 |
| `~/.ev_dashboard.html` | 临时 HTML 文件，pywebview 读取渲染 |
| `~/.ev_messages.json` | 消息数据缓存 |
| `~/.ev_visitors.json` | 访客数据缓存 |

## 总结

**"网页壳子"不是缺点，而是现代桌面应用的标准技术方案。**

- ✅ 开发效率高
- ✅ 样式灵活
- ✅ 跨平台兼容
- ✅ 内存占用低 (相比 Electron)
- ✅ 使用系统原生渲染引擎
