# EvNotifier 账号入口下沉 + 未登录门禁 方案

> 分析日期：2026-09-26　代码基线：`tools/ev-notifier/ev_notifier.py`（v2.3.31）
> 关联文档：`后台登录鉴权改造方案.md`（设备授权登录，阶段 1 已上线）、`面板技术说明.md`（顶部图标/菜单机制）
>
> **一句话**：把「登录 / 退出登录 / 退出软件」从顶部菜单**移进面板左下角**的账号小菜单；顶部菜单只留功能项；
> 未登录时面板先显示**登录引导页**，不登录看不到订单/消息等任何数据 —— 这就是常规的"受保护外壳 + 授权门"流程（对，标准做法）。

**需求解读（如有偏差请纠正）**：顶部菜单里不再出现 ①「登录 EvNotifier…」②「退出登录（清除本机凭据）」③「退出」（退出软件）三项；
它们统一收进面板**左侧底部**的账号区；点击账号区向上展开小菜单，里面有**版本号**和**退出**。

## 0. 结论速览

| 项 | 结论 |
|---|---|
| 交互方向 | 顶部菜单做"功能"，面板做"账号与退出" |
| 未登录门禁 | ✅ 标准流程、应当做：登录前不渲染任何数据页（订单/消息/访客/激活/走势/设备/轮询），只给引导页 |
| 实现代价 | 中等：门禁在**渲染层**一处判定 + **导航层**一处拦截即可，不需要改推送/补拉链路 |
| 最大风险 | ① 面板打不开时用户无法退出应用 → 必须留兜底入口；② 误判"未登录"会把用户锁在外面 → 判定只读本地凭据、并提供"重新检查" |
| 已可复用的能力 | 设备授权登录 `device_login()`、凭据状态 `_is_logged_in()/_auth_label()`、`ev://` 动作通道、`_device_login_worker()`、`api/ev.js?action=devices` |

放在 `sidebar-footer`（现在只有一个 Online 点），点击向上弹出面板内浮层（纯 HTML/CSS，不用原生菜单）：

```
│  │ 最后活跃：今天 10:37     │  │
│  │ ────────────────────   │  │
│  │ [登录] / [退出登录]      │  │  ← 按凭据状态二选一
│  │ 退出软件                │  │
│  └────────────────────────┘  │
│  ┌────────────────────────┐  │
│  │ [头像] foo@bar.com   ▾ │  │  ← 账号区（footer，常驻）
│  │        ● Online        │  │
│  └────────────────────────┘  │
└──────────────────────────────┘
```

要点：
- **未登录 / 凭据失效**：账号区显示「未登录，点这里登录」（红色小圆点 + 文案），小菜单里只有「登录 EvNotifier…」+ 版本号。
- **已登录**：显示邮箱（拿不到时退化为「本机设备名」）+ 连接状态点；小菜单里是「退出登录（清除本机凭据）」+ 版本号 + 「退出软件」。
- 小菜单动作走既有 `ev://` 通道：`ev://login` / `ev://logout` / `ev://quit-app` / `ev://device-me`（刷新账号信息）。
- 展开/收起：点账号区切换、点面板其它地方收起（`document.click` 判断 `closest`）、切换页面时收起。键盘可达（`tabindex` + Enter/Space）。
- 小菜单向上弹（`.sidebar-footer { position: relative }` + 菜单 `position:absolute; bottom:100%; left:8px; right:8px`），保证在小窗口里不被裁掉。

### 2.3 未登录门禁页（"先登录再看数据"）

任何数据页被请求时，若 `_is_logged_in()` 为假 → 整个 content 替换为引导页（**不渲染任何数据**）：

```
┌──────────────────────────────────────────────┐
│                    需要登录                    │
│                                              │
│  EvNotifier 通过「本机设备令牌」拉取通知与离线   │
│  消息。没有凭据时，订单、消息、访客数据都不会    │
│  显示。                                       │
│                                              │
│        [ 在浏览器里授权此设备 ]                │
│        [ 我已授权，重新检查 ]                  │
│                                              │
│  状态：未登录　|　凭据：无　|　上次检查 10:41    │
│  ⚠️ 需要联网完成一次授权（约 30 秒）           │
└──────────────────────────────────────────────┘
```

- 「在浏览器里授权此设备」→ `ev://login` → 起线程 `_device_login_worker()`（复用现有实现，含"登录进行中"防重复 + 成功/失败通知）。
- 登录成功 → `_refresh_content()` 自动回到**登录前想去的页面**（记录 `_gate_return_page`，默认 `messages`）。
- 凭据失效（`_auth_state == "invalid"`）→ 同一页，文案换成"本机凭据已失效（可能已在后台被撤销），请重新授权"。
- 引导页仍保留左下角账号区（否则登录入口就没了）。

## 3. 门禁（gate）实现设计

判定口径：**只看本地凭据，不联网**（离线也能"已登录"）：

```python
def _is_logged_in():        # :246 现有实现，直接复用
    return bool(DEVICE_TOKEN) or bool(SYNC_TOKEN)
```

| 层 | 做法 | 为什么两层 |
|---|---|---|
| **渲染层（主）** | `_build_current_html()` 开头：`if not _is_logged_in(): return self._html_login_gate()`（旁路所有 `_TAB_BUILDERS`） | 一处生效，8 个页面（含未渲染的占位页）都拿不到数据 |
| **导航层（兜底）** | `WebNavDelegate._handle_ev_url()` 的 `nav=` 分支：未登录 → 忽略导航、把 `_current_page` 固定在 gate、回 `ev://refresh` | 防前端 JS 直接改 `location` 绕过；也让"切页"在未登录时无声消失而不是白屏 |
| **动作层** | `login` / `logout` / `quit-app` 三个新 `ev://` 分支 | 账号区小菜单的落点 |

补充规则：
1. **登出后立即回门禁**：`ev://logout` → 清钥匙串 → `_auth_state="missing"` → `_current_page` 归位到 gate → `_refresh_content()`。**不**直接退出软件。
2. **凭据失效（401）**：`_on_auth_failed()` 里 `_auth_state="invalid"` → gate 接管；同时把通知文案从"点状态栏菜单 →「登录 EvNotifier…」"改成"打开面板 → 左下角账号区 → 登录"（`ev_notifier.py:361`）。
3. **顶部横幅**（`_html_wrap()` 的 `auth_banner`，`:4125`）保留但**只在非门禁页出现**（已登录但凭据失效的提示）；文案同样改成指向面板账号区。门禁页自己已经足够显眼，不需要重复。
4. **共享密钥算不算已登录？** 算（过渡期，`SYNC_TOKEN` 仍可用）。是否强制设备令牌见 §6 待确认 ①。
5. **离线用户**：从未登录过且无网 → 只能停在 gate（文案里说明"需要联网授权一次"）；曾登录过 → 本地令牌判定为已登录、正常看历史数据 ✓（不需要联网校验，因为补拉/推送本来就会各自报错）。
6. **门禁不拦设置页？** 不拦会更友好（可以改字号/通知开关），但它会泄露"应用装了"，不含业务数据 —— **默认一并拦**（口径统一：未登录 = 什么都看不到），如想例外见待确认 ②。

## 5. 验收标准

1. 未登录（清空钥匙串 + 无 `EV_SYNC_TOKEN`）打开面板：**任何页面都看不到数据**，只有引导页；点侧栏「订单列表」不切换（停在引导页）。
2. 引导页点「在浏览器里授权此设备」→ 浏览器打开 `/ev-login` → 授权后 ≤5 秒面板自动变为数据页，且回到登录前想去的页面。
3. 已登录时打开面板：直接进数据页，账号区显示邮箱/本机名 + 绿点。
4. 账号区点击 → 小菜单**向上**弹出，含**版本号**与**退出软件**；点面板空白处收起。
5. 小菜单「退出登录」→ 凭据清除、面板**立刻回到引导页**（应用不退出）；顶部菜单里找不到任何注销/退出项。
6. 小菜单「退出软件」→ 应用退出（PID 消失、`~/.ev_notifier_state.json` 记为正常退出，不污染崩溃计数）。
7. 顶部菜单项顺序：打开面板 → 状态行 → 暂停 → 运行状态 → 调试日志 → 截图 → 重启 → 版本（**无账号项、无退出**）。
8. 凭据失效场景：后台撤销设备 → 下次请求 401 → 面板自动回引导页，通知文案指向"面板左下角账号区"。
9. 回归：`./tools/ev-notifier/tests/run_tests.sh` 全绿（含新增门禁用例）。

## 7. 风险与兜底

| 风险 | 处理 |
|---|---|
| **面板打不开 → 无法退出**（退出入口只存在于面板里） | ① 兜底命令行：`launchctl bootout gui/$(id -u)/com.evnotifier.agent`（停常驻）或 `pkill -f ev_notifier.py`；② 建议按待确认 ④ 保留隐藏入口；③ `quit_app` 逻辑本身没变，风险只在"入口可达性" |
| **误判未登录把用户锁在外面**（钥匙串读取失败 / 主机改名） | `_is_logged_in()` 只在内存无值时读一次钥匙串，失败**不缓存 False**；门禁页提供「我已授权，重新检查」按钮（重新读钥匙串 + `_auth_label()` 回显真实原因）；文案区分"无凭据 / 凭据失效 / 读取失败" |
| 门禁页反复重建导致闪烁 | 门禁是纯字符串渲染，无网络请求；`_switch_to` 被拦时直接 `return`（不触发 `_refresh_content`） |
| 在 WebView 里同步 `terminate_` 可能踩 runloop 栈 | 退出走 `AppHelper.callLater(0.1, ...)`（与开面板同一纪律） |
| 小菜单被窗口边缘裁切 | `sidebar-footer` 固定高度 + 菜单 `bottom:100%`、`max-height` + 内部滚动；窗口最小 900×560（`setMinSize_`）足够 |

```js
function toggleAccountMenu(ev) {
  var box = document.getElementById('accountBox');
  if (!box) return;
  if (ev) { ev.stopPropagation(); }
  box.classList.toggle('open');
}
document.addEventListener('click', function(e) {
  var box = document.getElementById('accountBox');
  if (box && !box.contains(e.target)) { box.classList.remove('open'); }
});
```
