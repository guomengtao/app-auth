## 1.5 三条凭据通道：谁是"真实登录"，env 是额外还是配合？（回答你的问题）

| 通道 | 本质 | 能否逐台撤销 | 能否审计 | 获取方式 | 现状用途 | 定位 |
|---|---|---|---|---|---|---|
| ① **设备令牌** `x-ev-device-token` | 后台账号在浏览器里授权一次 → **每台设备一枚**，存 macOS 钥匙串 | ✅ 后台逐台撤销 | ✅ 有 label / email / last_seen / ip | 需浏览器授权一次 | 主通道 | **真实登录**（唯一算"已登录"的通道） |
| ② **共享密钥** `EV_SYNC_TOKEN`（header `x-ev-sync-token`） | Vercel Production Secret 与本机 `.env` 里**同一把字符串** | ❌ 只能整体换密钥（所有机器一起换） | ❌ 无法区分是哪台机器 | 纯配置，不需要浏览器 | 过渡期兼容、脚本/自动化、排障 | **额外（并行）通道** |
| ③ 后台 cookie | 后台面板登录态（自签 HMAC + `ADMIN_EMAIL` 白名单） | ✅ | ✅ | 浏览器 | 仅供浏览器页面 | 浏览器专用 |

**判定依据（不是猜的）**：服务端 `clientHasAccess()` 的实现就是三个**并列分支** —— ①设备令牌 → ②共享密钥 → ③cookie，且 `EV_AUTH_MODE=strict` 时②被摘掉。也就是说：

- 从**服务端视角**看，② 是一条**可选的额外通道**，不是登录链路的一环（登录链路是"浏览器里用 ③ 授权 → 产出 ①"）。
- 从**运行现状**看，② 起到的是**运维/应急兜底**作用（脚本、cron、`delivery-*` 排障、以及"还没做设备登录的老机器"）。
- 所以它**不是"配合方式"**（真实登录不依赖它），并且**不能当登录态**：它没有账号身份、不能撤销、无法审计 —— 拿它当"已登录"会让门禁形同虚设。

**定稿做法**：

1. **UI 门禁只认 ①**（`DEVICE_TOKEN`）；`_is_logged_in()` 去掉 `or SYNC_TOKEN`。
2. ② 继续保留在服务端（**不改 `EV_AUTH_MODE`**），供自动化/排障使用；但面板不把它当登录。
3. 若某台机器只有 ②：面板被门禁挡住，登录页明确提示
   > 检测到**共享密钥（运维通道）**：它不是账号登录，无法撤销/审计。请用浏览器授权一次。
4. 将来若要彻底废掉 ②：先确认没有脚本依赖 → 再切服务端 `EV_AUTH_MODE=strict` → 本机删掉 `.env` 里的 `EV_SYNC_TOKEN`。（本次不做）

## 3. 门禁（gate）实现

| 层 | 做法 | 位置 |
|---|---|---|
| **判定** | `_is_logged_in()` **只看设备令牌**（去掉 `or SYNC_TOKEN`）；另加 `_has_saved_login()`（钥匙串里有令牌 = 可"直接登录"） | `ev_notifier.py:246` |
| **渲染层（主）** | `_build_current_html()` 开头：未登录 → 直接 `return self._html_login_gate()`，旁路全部 `_TAB_BUILDERS`（**含设置页**） | `:5810` |
| **导航层（兜底）** | `WebNavDelegate._handle_ev_url()` 的 `nav=` 分支：未登录 → 忽略导航、`_current_page` 固定为 gate | `:3590` |
| **动作层** | 新增 `ev://login` / `ev://logout` / `ev://account-refresh` | `:3590` |

补充规则：
1. `_gate_return_page`：登录成功后回到登录前想去的页面（默认 `messages`）。
2. 凭据失效（401）：`_on_auth_failed()` 置 `_auth_state="invalid"` → 门禁接管；把通知文案与 `auth_banner`（`:4125`）里"点状态栏菜单 → 登录"改成**"面板 → 左下角账号区 / 登录页"**（`:361`）。
3. 门禁是纯字符串渲染（无网络请求），切页被拦时直接 `return`，不触发刷新闪烁。
4. 未登录时的后台行为不变：**推送/补拉照旧尝试**（有 env 密钥的机器仍能收通知），只是面板不给看数据。

## 4. 登录信息保存与「直接登录」（反馈 4）

### 4.1 两级登出 + 退出软件，职责分离

| 动作 | 入口 | 行为 | 钥匙串 |
|---|---|---|---|
| **退出登录** | 面板账号区（唯一入口） | 软登出：清内存令牌、断开订阅、回登录页；登录页出现「直接登录（邮箱）」 | **保留** |
| **清除本机登录信息** | **设置页 → 账号区块** | 硬登出：删钥匙串（换机 / 离职 / 怀疑泄漏时用），登录页不再出现"直接登录" | 删除 |
| **退出（关闭软件）** | 顶部菜单 | 关软件；**不再** `disable_auto_start()`；钥匙串不动 → 下次打开仍已登录 | 保留 |

> 提醒文案要写清：账号区的小菜单里给「退出登录」加一行灰字说明"不会删除本机保存的登录信息"。

### 4.2 「保存登录信息」勾选（登录页）

| 选项 | 行为 |
|---|---|
| ☑ 勾选（默认） | 令牌写钥匙串 → 下次启动 / 软登出后点「直接登录」即可，无需浏览器 |
| ☐ 不勾选 | 令牌只留在本次运行的内存（会话级）→ 重启需重新授权（适合公用/临时机器） |

实现：`device_login(interactive=True, timeout=600, save=True)` 透传；`save=False` 时走 `_keychain_delete_token()` 且只在内存持有 `DEVICE_TOKEN`。
「直接登录」按钮 = 读钥匙串 → `DEVICE_TOKEN` → `_auth_state="ok"` → 强制补拉一次 → 回 `_gate_return_page`（**秒级、无浏览器**）。

### 4.3 账号信息与「最后活跃时间」（反馈 5）

- 服务端新增 `GET /api/ev.js?action=device-me`（带 `x-ev-device-token`）→ 返回
  `{ email, label, created_at, last_seen_at, last_seen_ip }`。
  `lib/device-token.js` 的 `validateDeviceToken()` 已经返回 `{id, email, label}` 并会节流更新 `last_seen_at`，**再加一个按 token 查 last_seen 的查询即可（约 10 行）**。
- 客户端缓存 `~/.ev_account.json`：`{email, label, created_at, last_seen_at, fetched_at}`；
  刷新时机 = 登录成功 / 每次补拉成功（节流 1h）/ 小菜单里手动点「刷新」；菜单直接读缓存（不每次打接口）。
- 显示格式统一用已有 `_fmt_bj()`（北京时间）：`今天 10:37` / `昨天 22:05` / `2026-09-25 22:05`。
- 拿不到时退化为：只显示邮箱（`DEVICE_TOKEN` 存在但接口失败）或「本机设备」。

## 5. 开机自启（反馈 3）

现状与坑：

- `ensure_auto_start()`（`:366`）**每次启动都无条件重写 plist**（`RunAtLoad` + `KeepAlive`）→ 等于"强制开"；
- `quit_app()`（`:6019`）会调 `disable_auto_start()`（`:393`，删 plist + `launchctl bootout`）→ 即"退出软件就关自启"；
- 设置页目前只把 `LAUNCH_AGENT_PATH` 当信息行展示（`:5478`），**没有开关**；`get_auto_start()` = plist 是否存在（`:406`）。

改造：

1. **偏好落盘**：`load_notify_settings()`（`:410`）新增键 `auto_start`，默认 `True`（与其它开关同一文件 `~/.ev_notify_settings.json`）。
2. **启动时尊重偏好**：
   ```python
   if load_notify_settings().get("auto_start", True):
       ensure_auto_start()      # 保留"plist 自愈"（brew 升级 python 路径变化也能修正）
   else:
       disable_auto_start()
   ```
   ⚠️ 关键：**关闭后必须真的不再自动开启**（否则用户手动启动一次就被偷偷改回 ON —— 这是这类开关最常见的坑）。
3. **设置页新增一行**「开机自启」：ON/OFF 切换，走 `ev://setting=auto_start` → `_toggle_auto_start()`（写偏好 + 立即 `enable/disable` + 刷新页面 + debug log）。
4. **`quit_app()` 删掉 `disable_auto_start()`**：顶部「退出」只关软件，不动自启设置。

## 7. 验收标准

1. **未登录**（清钥匙串 + `.env` 里只有共享密钥）打开面板：任何页面（**含设置页**）都只看到登录页；点侧栏其它页面不切换。
2. 登录页只有：主按钮、`保存登录信息`勾选、`直接登录`（有保存时）、`我已授权，重新检查`、状态行 —— 无其它入口。
3. 勾选"保存登录信息"完成登录 → 重启应用/退出登录后再次打开：登录页出现「直接登录（邮箱）」，**点一下即可进入，无需浏览器**。
4. 面板账号区点击 → 向上弹小菜单，含 **版本号**、邮箱、本机名、**最后活跃时间**、**退出登录**；**没有**"退出软件"。
5. 点「退出登录」→ 回登录页（应用不退出），钥匙串仍在 → 可「直接登录」；设置页点「清除本机登录信息」→ 登录页不再有「直接登录」。
6. 顶部菜单：**保留**「退出」（关闭软件）；不再有「登录」「退出登录」；顺序与 §2.1 一致。
7. 顶部「退出」关闭软件后：**开机自启设置不变**（对照 plist 是否仍在 + `launchctl print gui/$(id -u)/com.evnotifier.agent`，退出前后一致）；`~/.ev_notifier_state.json` 记为正常退出。
8. 设置页「开机自启」切换 OFF → 立即 `bootout` + 删 plist；**再手动启动应用后仍是 OFF**（不会被偷偷打开）；切回 ON → plist 重建并 `bootstrap`。
9. 账号区显示的最后活跃时间为**北京时间**（用 `_fmt_bj`），与后台「设备」列表一致。
10. 回归：`./tools/ev-notifier/tests/run_tests.sh` 全绿（含 §6-15 新增用例）。

## 9. 风险与兜底

| 风险 | 处理 |
|---|---|
| 面板打不开时无法退出应用 | ✅ **已消除**：「退出」保留在顶部菜单（这正是把"关软件"留在系统菜单的价值） |
| 软登出被误解为"已清除本机信息" | 小菜单里「退出登录」下方加灰字说明；设置页明确「清除本机登录信息」是另一个动作 |
| 严格门禁对旧机器的成本 | 一次性：登录一次（浏览器授权约 30 秒）；登录页文案写清"为什么需要登录" |
| 关闭自启被"手动启动一次又打开" | 启动逻辑读偏好（§5-2），并加测试用例（§7-8） |
| 在 WebView 栈里同步做重活（开门禁/登录） | 所有真动作（登录线程、刷新）走 `AppHelper.callLater` 或后台线程（与 `open_dashboard` 同一纪律） |
| 门禁与"未读徽标"冲突 | 未登录时顶栏标题仍是未读数（那是推送侧信息，不泄露业务数据）；门禁只挡面板内容 |
