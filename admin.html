🧰 同步操作区
⬆⬇ 一键双向同步 (merge)
① 拉取服务器最新快照合并到本地 → ② 收集本地未同步变更推送到服务器 → ③ 用服务器最终快照覆盖本地，保证一致。这是最推荐的日常操作。
⬇ 仅拉取 (pull)
用服务器数据强制覆盖本地。适用于：换设备登录、想丢弃本地改动、怀疑本地数据损坏时。本地所有未推送改动会被覆盖丢失！
⬆ 仅推送 (push)
只把本地的新增/编辑/删除推送到服务器，不会主动合并服务器上已有的新数据。适合离线批量操作后集中上传。

🛡️ 删除保护

这是最关键的安全设置 — 防止本地"删除标记"同步时误删线上数据。

🟢 推送前校验删除目标是否存在于服务器
推送删除操作前，先去 Postgres 查询该 ID 是否真的存在。如果服务器上没有这条数据（说明之前 pull 失败或从未同步过），就拒绝删除。这能彻底避免本地孤立的删除标记被推到线上造成数据丢失。强烈建议保持开启。
🟡 删除前二次确认弹窗
任何删除产品/兑换码操作都会弹出确认框，防止误点。
🔄 成功同步后自动清理删除标记
每次 pull/push/merge 成功后，自动清空本地的 deletedProductIds / deletedRedeemCodes。推荐开启，避免删除标记堆积。

💾 数据管理

导出/导入方便备份、迁移或在多台设备之间手动同步。清空本地数据只影响当前浏览器，服务器 Postgres 数据完全不受影响。

ℹ️ 关于数据同步的安全机制

🔒 写入保护
Merge 模式下，服务端数据 updated_at 更新才覆盖本地，避免旧数据回刷新数据。
🧯 异常检测
Pull 时如果发现服务器数据量比本地少 90% 以上（50 → 3），会自动中止 replace 保护本地。
📛 删除白名单
删除操作只允许推送到服务器上已存在的目标。本地删除了一个服务器上根本没有的 ID → 拒绝。
🔐 鉴权保护
所有 /api/admin/* 路由需要 JWT token，未授权返回 401。activate 不走这个通道。
